# V6 近期工作汇报

更新时间：`2026-05-12`

## 1. 汇报背景

本阶段工作主要覆盖 `V4.7` 到 `V5`。整体目标是把项目从“功能基本打通”推进到“闭环稳定可跑、多人协同可治理、主动学习可追踪”的状态。

相比早期阶段，这一轮工作的重点已经不再是补单个页面，而是：

- 把训练、预测、CoreSet、题池治理串成稳定闭环
- 把多人标注、争议复核和审核日志做成可追踪流程
- 把性能和可维护性问题提前收口，为后续正式评估和上线准备打基础

## 2. 本阶段完成的核心工作

### 2.1 V4.7：主动学习训练闭环与训练监控优化

这一阶段主要完成了训练链路稳定化和训练监控可用化：

- 修复训练样本统计与“合并金标”开关不一致的问题
- 支持初中 / 高中训练学段切换
- 落地 GPU Worker 方案，支持 Web 服务环境与 GPU 训练环境分离
- 修复 `model_versions` 落库失败问题，完善模型类型和来源信息记录
- 补齐随机种子与确定性控制，使同参数训练结果具备可复现性
- 优化训练任务、模型版本、趋势图之间的关联展示

阶段意义是：训练不再只是“能跑通”，而是开始具备“可重复、可跟踪、可治理”的基础能力。

### 2.2 V4.8：训练页与嵌入可视化优化

这一阶段主要围绕管理体验和可视化性能展开：

- 为题目 embedding 可视化增加后端结果缓存和前端请求缓存
- 优化 4 万级点位渲染性能，减少页面重复全量计算
- 打通可视化与统一题池详情跳转
- 优化训练页默认参数、设备语义和顶部摘要布局
- 统一长任务名和模型名的短名展示与 Tooltip 说明

阶段意义是：大规模题库可视化和训练管理页从“能看”提升为“能顺畅使用”。

### 2.3 V4.10：题池治理与系统管理员能力补强

这一阶段重点补齐系统管理员治理能力：

- 登录页补齐开发账号与多标注员联调入口
- 统一题池支持按状态快速查看
- 管理后台支持题池回收、批次撤回、重新选题
- 低置信度预测选题与 CoreSet 选题结果开始具备批次治理能力

阶段意义是：主动学习闭环从“能生成结果”推进到“结果可回收、可撤销、可重跑”。

### 2.4 V5：多人标注、复核闭环与主动学习治理继续完善

进入 `V5` 后，重点工作转向多人协同和主动学习质量治理：

#### 多人标注与复核

- 支持同题多标注员并行标注
- 规定每题至少 3 人完成标注
- 设计并实现按维度多数表决的一致性算法
- 争议题自动进入复核员队列，不再依赖系统管理员手工打回
- 管理员可查看标注员、复核员全链路处理记录
- 新增审核日志与操作历史

#### 培训与准入体验

- 培训校准题改为一次只做一道题
- 在培训中补充素养定义和引导样例
- 正式标注页支持鼠标悬浮查看素养说明
- 标注员、复核员工作台与历史记录页按角色拆分

#### 主动学习与 CoreSet

- CoreSet 由同步请求改为异步后台任务
- 管理后台可查看历史任务、运行阶段、失败原因和批次结果
- 默认 `Epochs` 调整为 20，CoreSet 默认策略调整为 `K-Means`
- 题池治理和批次结果展示闭环补齐
- 基于全量 embedding 的 CoreSet 正式落地
- 新增增量更新模式：后续导入新题后，可以只对新增未标注题执行增量 CoreSet

阶段意义是：系统开始同时具备“多人协同稳定跑”和“主动学习持续迭代”的双重能力。

## 3. 这一阶段解决的关键问题

本阶段实际解决的不是零散小问题，而是几类关键瓶颈：

1. 训练链路不稳定  
通过 GPU Worker、确定性控制、模型版本落库修复，把训练从实验状态拉回到可复现实用状态。

2. 大规模题库页面卡顿  
通过 embedding 可视化缓存和渲染优化，使 4 万级题库页面具备基本可用性。

3. 选题结果不可治理  
通过题池回收、批次撤回、历史任务记录，把主动学习结果纳入治理闭环。

4. 多人标注难以收敛  
通过三人并行标注、多数聚合、争议复核与审核日志，让标注闭环有了清晰规则。

5. 新导入数据无法平滑接入主动学习  
通过 embedding 增量补全和 CoreSet 增量更新模式，实现“老数据不动，新数据单独增量补选”。

## 4. 当前系统状态

截至目前，系统已经具备以下比较完整的闭环：

- 多源题库导入与统一题池
- 题目 embedding 生成与可视化
- 标注员培训准入
- 多人并行标注
- 三人聚合与争议复核
- 主动学习训练
- 低置信度预测选题
- CoreSet 全量 / 增量选题
- 题池治理、回收与批次撤回
- 历史任务、操作日志与角色工作台

可以认为系统已经从“原型联调阶段”进入“稳定迭代阶段”。

## 5. 当前仍需继续推进的方向

虽然主闭环已经打通，但还有几类能力建议继续推进：

1. 正式评估体系  
建设固定测试集、交叉验证、重复实验和效果报表，用于更严谨地证明模型改进。

2. 算法质量指标在线化  
把 Coverage、Redundancy、MMD 等指标纳入 CoreSet 结果，增强可解释性。

3. 更细粒度的治理能力  
继续补失败恢复、回滚、批次备注、策略对比等功能。

4. 上线前安全与运维准备  
包括密码加密、权限边界、监控告警、日志归档和备份恢复。

## 6. 阶段结论

从 `V4.7` 到 `V5`，本阶段最重要的成果不是单个页面或单个接口，而是把系统的几条主链路真正做成了“能运行、能复现、能治理、能扩展”的形态。

如果用一句话总结，这一阶段完成的是：

“把 K12 学科核心素养标注平台，从单点功能联调，推进到了多人协同标注与主动学习闭环可持续迭代的阶段。”
