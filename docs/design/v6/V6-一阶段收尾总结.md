# V6 一阶段收尾总结

更新时间：`2026-05-13`

## 1. 阶段结论

K12 学科标注平台一阶段初版系统已经完成。

当前系统已经不再只是页面原型或单点功能联调，而是具备了从题库导入、题目治理、培训准入、多人标注、争议复核到主动学习选题和模型训练监控的完整主链路。

一阶段可以定义为：完成初版系统主体功能，具备本地运行、演示汇报、流程验证和继续迭代的基础。

## 2. 已完成的核心模块

### 2.1 项目总览

项目总览用于展示系统总体状态，包括题库规模、标注进展、复核进展、训练状态和下一步建议。

该模块的价值是让管理员进入系统后能够快速知道当前项目处于什么状态。

### 2.2 导入中心

导入中心已经支持题库文件导入、批次记录、批次详情和导入结果查看。

当前已优化分页展示，避免大量导入记录堆叠在同一页面。

### 2.3 判重复核

系统支持对疑似重复题进行人工复核，帮助保证统一题池的数据质量。

判重复核与导入流程、统一题池治理形成连接。

### 2.4 统一题池

统一题池作为题目集中管理入口，支持查看题目状态、来源、标注状态和题目详情。

它是系统管理员理解题库全貌和追踪单题状态的核心页面。

### 2.5 可视化

可视化模块支持基于题目 embedding 的降维展示，可以查看题库分布、标注状态和缺失 embedding 情况。

该模块已经具备 4 万级题目数据的基本可用性，并支持一键补全缺失 embedding。

### 2.6 管理后台

管理后台承担系统治理功能，包括审核日志、操作历史和管理行为追踪。

题池治理和 CoreSet 历史任务已更适合放入训练监控链路中，因此管理后台主要回归“治理与审计”定位。

### 2.7 训练监控

训练监控已经成为主动学习闭环的主入口。

当前支持：

- 模型训练
- 训练日志
- 模型版本管理
- 低置信度预测选题
- CoreSet 全量选题
- CoreSet 增量选题
- CoreSet 历史任务
- 失败原因和运行阶段查看
- 题池治理和批次撤回

## 3. 角色侧能力完成情况

### 3.1 系统管理员

管理员已具备完整管理链路：

- 导入题库
- 处理重复题
- 查看统一题池
- 查看 embedding 可视化
- 管理训练与主动学习选题
- 查看 CoreSet 历史任务
- 治理题池批次
- 查看审核日志和操作历史

### 3.2 标注员

标注员已具备完整标注链路：

- 查看个人工作台
- 完成初中/高中培训准入
- 学习核心素养定义和引导样例
- 一次一题完成实战校准
- 查看结果复盘
- 支持全部重做和错题重做
- 领取题目进行正式标注
- 查看自己的标注记录

### 3.3 复核员

复核员已具备争议题处理链路：

- 查看待复核数量
- 选择领取复核题数量
- 查看争议素养
- 查看三名标注员的标注情况和确信程度
- 提交最终复核结论
- 查看已复核题目

## 4. 多人标注与一致性规则

一阶段已经完成多人标注闭环设计与实现。

当前规则为：

- 每道题至少需要三名标注员完成标注。
- 每个素养维度独立判断一致性。
- `0级` 表示不体现该素养。
- 如果三人中至少两人在某个素养层级上一致，则该素养采用多数结果。
- 如果某个素养三人意见均不同，则该素养进入争议。
- 存在争议素养的题目自动进入复核员队列。
- 复核员只处理争议素养，已一致的素养可直接锁定。

这一规则兼顾了可解释性、实现复杂度和实际标注效率。

## 5. 主动学习闭环完成情况

当前主动学习流程已经形成可运行闭环：

1. 基于已有金标数据训练模型。
2. 对未标注题进行预测。
3. 使用低置信度策略选择模型不确定题。
4. 使用 CoreSet 策略选择代表性题目。
5. 将选题结果加入待标注池。
6. 标注员完成多人标注。
7. 复核员处理争议题。
8. 高质量数据回流，用于下一轮训练。

CoreSet 已支持：

- K-Means 覆盖
- facility location
- graph cut
- MoE 融合策略
- 全量未标注池选题
- 新导入数据增量更新
- 异步任务执行
- 历史任务查看
- 失败原因查看
- 批次撤回

## 6. 一阶段解决的主要问题

### 6.1 从页面原型到业务闭环

早期系统主要是页面、接口和数据模型逐步联调。

当前系统已经能够串起真实业务流程：导入题目、培训标注员、多人标注、复核争议、训练模型、再次选题。

### 6.2 从单人标注到多人协同

系统不再依赖单个标注员结果，而是通过三人标注、多数一致和复核员仲裁提高数据质量。

### 6.3 从同步选题到异步治理

CoreSet 选题不再依赖前端长时间等待，而是通过异步任务、历史记录、阶段状态和失败原因进行治理。

### 6.4 从静态题池到主动学习循环

题库不再只是静态数据集合，而是可以通过模型训练、低置信度预测和 CoreSet 代表性选题持续推动标注迭代。

### 6.5 从功能可用到体验可解释

培训准入、结果复盘、错题重做、素养悬浮说明、历史记录选择等优化，让标注员更容易理解为什么这样标。

## 7. 当前仍需注意的问题

一阶段已经完成初版主体能力，但还不是生产上线版本。

后续仍建议继续完善：

- 正式测试集和评测报告
- 模型效果对比实验
- CoreSet 结果质量指标，如覆盖度、冗余度、代表性
- 专家金标解释字段
- 更严格的权限边界和安全策略
- 部署脚本、日志归档和备份恢复
- 大规模并发下的性能压测
- 数据库迁移脚本与环境初始化流程统一

## 8. 二阶段建议方向

二阶段不建议继续盲目堆功能，而应重点推进“可评估、可部署、可运维、可解释”。

建议优先级：

1. 建立正式评测体系，固定测试集和模型指标。
2. 完善生产部署方案，包括环境变量、数据库迁移、Redis/Celery 和日志。
3. 强化权限与安全，避免开发账号和弱密码进入生产环境。
4. 完善主动学习策略评估，比较低置信度、CoreSet 和混合策略效果。
5. 增加金标理由和复核理由沉淀，提升培训和争议处理的可解释性。
6. 对大规模数据导入、选题、训练和可视化做性能压测。

## 9. 最终总结

一阶段已经完成“从 0 到 1”的系统建设。

当前系统已经具备：

- 可运行的前后端工程
- 可复用的数据库与业务模型
- 可操作的管理员、标注员、复核员角色流程
- 可追踪的多人标注和复核闭环
- 可执行的主动学习训练和 CoreSet 选题链路
- 可用于汇报演示的文档和操作手册

因此，项目一阶段可以正式收尾。

后续工作应进入二阶段，以评测、部署、安全、稳定性和算法质量提升为主。
