## 2. 前端技术方案

### 2.1 技术选型

前端建议采用以下组合：

- `React 18`
- `TypeScript`
- `Vite`
- `React Router`
- `Ant Design`
- `TanStack Query`
- `Zustand`
- `Axios`
- `ECharts`
- `dayjs`

### 2.2 为什么这样选

#### `React + TypeScript + Vite`

原因：

- 启动快，适合当前 0 到 1 阶段
- 组件化能力强，方便把标注页、可视化页、管理页拆成独立模块
- TypeScript 能约束接口类型，减少后续字段调整带来的联调错误

#### `Ant Design`

原因：

- 后台型系统成熟稳定
- 表格、表单、分页、抽屉、Tabs、树、上传组件都比较完善
- 很适合管理员后台、导入任务、题库列表、训练任务监控这类页面

#### `TanStack Query`

原因：

- 管理服务端数据很稳
- 适合处理题库列表、导入批次、标注任务、训练任务、可视化数据等查询缓存
- 能减少“页面切换后重复请求”和“手动维护 loading/error 状态”的成本

#### `Zustand`

原因：

- 轻量，适合存放会话级状态
- 比如：当前登录用户、当前选中的题目、标注草稿、本地筛选状态、布局偏好
- 不需要上来就引入更重的状态库

#### `ECharts`

原因：

- 适合做可视化大屏、主动学习曲线、分布散点图、统计图表
- 与后台管理类页面风格兼容
- 后续做题目嵌入降维散点图和训练效果曲线会比较顺手

## 3. 前端设计思路

### 3.1 总体原则

前端整体采用：

- 桌面端优先
- 模块化页面组织
- 读写分层
- 统一题池视角

含义是：

- 标注主工作流优先保证桌面端效率
- 题库、标注、导入、推荐、训练、管理后台按业务模块拆开
- 查询状态和本地交互状态分开管理
- 页面始终围绕统一 `question_id` 展开，而不是围绕某个原始数据源展开

### 3.2 页面分层

建议分成 4 层页面：

#### `public`

- `/login`
- `/register`

#### `onboarding`

- `/onboarding`

#### `workspace`

- `/annotate`
- `/questions`
- `/imports`
- `/visualization`
- `/training`

#### `admin`

- `/admin/users`
- `/admin/questions`
- `/admin/imports`
- `/admin/dedup-review`
- `/admin/system`

### 3.3 最先做的页面

前端第一阶段不需要把所有页面一次做完，建议按这个顺序：

1. 登录页
2. 系统主框架页
3. 题库列表页
4. 标注工作台
5. 导入批次页
6. 题目详情抽屉/详情页

原因：

- 这些页面直接支撑“导入 -> 查题 -> 标注 -> 聚合”主链路
- 可视化、训练监控、复杂后台属于第二阶段

## 4. 页面与模块设计

### 4.1 主框架布局

建议采用：

- 左侧导航
- 顶部状态栏
- 中间主内容区
- 局部抽屉/弹窗承载详情和批量操作

左侧导航建议包含：

- 首页
- 题库
- 标注
- 导入
- 可视化
- 训练
- 管理后台

顶部状态栏建议包含：

- 当前模块标题
- 全局搜索入口
- 当前用户
- 系统状态

### 4.2 标注工作台

这是前端最核心页面，建议沿用 V1 的左右分栏思想：

- 左侧：题目列表、筛选器、推荐入口、标注进度
- 右侧：题干、答案/解析折叠区、核心素养矩阵、自信度、保存/提交按钮

关键组件建议拆分为：

- `QuestionListPanel`
- `QuestionFilterBar`
- `QuestionPreviewCard`
- `AnnotationWorkspace`
- `CompetencyMatrix`
- `AnnotationHistoryPanel`
- `RecommendationBadge`

### 4.3 导入管理页

建议作为管理员与运营观察页面，核心是“看得懂导入状态”。

页面内容包括：

- 导入批次表格
- 批次状态统计卡片
- 原始记录数量
- 成功/失败数量
- 失败原因抽屉
- 未来接入判重后的命中统计

后续这里还要增加：

- 归一化入库进度
- 判重结果分布
- 疑似重复候选入口

### 4.4 题库页

题库页和标注页分开更清晰。

题库页主要负责：

- 统一题池检索
- 查看题目详情
- 按学科/年级/题型/状态筛选
- 查看来源映射、知识点、目录、金标准标签、考试行为摘要

这会是后续观察判重和归一化导入成果的重要页面。

### 4.5 管理后台

管理员后台建议重点做 4 个页面：

- 用户与角色管理
- 导入任务管理
- 题目管理
- 判重复核管理

其中“判重复核管理”后续会成为非常关键的页面，用于处理：

- `PENDING_REVIEW`
- `CONFLICT_DETECTED`
- 合并确认
- 错误合并回滚

### 4.6 可视化与训练页

这两类页面建议第二阶段再细做，但第一版可以先预留只读页。

可视化页先展示：

- 题量统计
- 已标注/未标注占比
- 推荐批次趋势
- 后续接 2D 降维散点图

训练页先展示：

- 训练任务列表
- 任务状态
- 指标卡片
- 主动学习曲线

## 5. 前端目录建议

建议采用下面的前端结构：

```text
frontend/
  src/
    app/
      App.tsx
      providers/
      store/
    router/
      index.tsx
      guards.tsx
    layouts/
      AppShell/
      AuthLayout/
    pages/
      login/
      onboarding/
      questions/
      annotate/
      imports/
      visualization/
      training/
      admin/
    modules/
      auth/
      question-bank/
      annotation/
      import-center/
      recommendation/
      analytics/
      training/
    components/
      common/
      charts/
      question/
      annotation/
    services/
      api-client.ts
      auth.ts
      questions.ts
      imports.ts
      annotations.ts
      training.ts
    hooks/
    types/
    utils/
    styles/
```

### 5.1 为什么这样拆

- `pages` 放路由页面
- `modules` 放业务能力和组合组件
- `components` 放可复用通用组件
- `services` 统一管理 API 调用
- `types` 存接口 DTO 与前端视图模型

这样后面新增模块时，不会把代码都堆在 `pages` 里。

## 6. 前端状态管理建议

### 6.1 服务端状态

交给 `TanStack Query`：

- 题库列表
- 题目详情
- 导入批次
- 标注任务
- 推荐结果
- 训练任务
- 可视化数据

### 6.2 本地会话状态

交给 `Zustand`：

- 当前用户信息
- 当前选中的题目
- 标注草稿
- 当前筛选条件
- 页面布局状态

### 6.3 表单状态

优先采用 `Ant Design Form` 即可。

原因：

- 和后台型系统契合
- 登录、用户编辑、筛选器、导入触发等都足够用
- 当前阶段不急着再叠加别的表单库

---

## 7. 与后端的接口对接方式

前端应该按业务模块组织接口，而不是按页面组织。

例如：

- `services/questions.ts`
  - `getQuestionList`
  - `getQuestionDetail`

- `services/imports.ts`
  - `getImportBatches`
  - `runLocalImport`

- `services/annotations.ts`
  - `claimTask`
  - `saveDraft`
  - `submitAnnotation`

后续正式接入时，要注意 3 点：

1. 所有接口 DTO 独立定义
2. 后端字段名尽量直接复用，不做过度二次转换
3. 对长列表页统一做分页和筛选器封装

## 10. 建议的前端开发顺序

建议按以下顺序推进前端：

### 第一步：搭前端工程底座

- 初始化 `frontend`
- 接入 `React + Vite + TypeScript`
- 配置 `Ant Design`
- 配置 `React Router`
- 配置 `TanStack Query`
- 配置 `Zustand`
- 建立基础布局和路由骨架

### 第二步：先做观察型页面

先做最容易观察系统状态的页面：

- 登录页
- 首页/总览页
- 导入批次页
- 题库列表页
- 题目详情抽屉

这样你很快就能看到：

- 数据是否进来了
- 题目是否进入统一题池
- 判重是否开始生效

### 第三步：再做标注主页面

- 题目列表
- 标注工作区
- 核心素养矩阵
- 草稿保存/提交

### 第四步：再做后台复核页

- 判重候选复核
- 题目合并确认
- 导入异常处理

### 第五步：最后接可视化和训练监控

- 可视化大屏
- 训练任务页
- 推荐结果页

## 11. 我建议你现在优先关注的观察点

为了便于你后续看项目进度，最值得观察的不是页面数量，而是下面几个里程碑：

1. 是否已经能把真实数据导入 `source_question_records`
2. 是否已经能归一化落到 `questions`
3. 是否已经能通过判重规则命中已有题
4. 是否已经能在前端题库页看到统一题池
5. 是否已经能在标注页完成一次完整标注提交

只要这 5 个点逐步打通，项目就已经从“设计阶段”进入“可运行阶段”了。
