# V2 文件夹批量导入说明

## 1. 功能目标

这个功能用于支持下面这类真实场景：

- 一个目录下有很多 `dataset2_question_json` 格式的 `.json` 文件
- 希望一次性上传整个目录，而不是一个文件一个文件手动点
- 导入后仍然保留现有的统一题池归一化和判重能力

当前版本已经支持把**一个文件夹中的多个文件合并成同一个导入批次**。
对于超大目录，前端会自动按固定大小分片上传，而不是一次性把所有文件塞进一个请求。

---

## 2. 当前支持范围

### 2.1 支持的数据源

- `dataset2_question_json`
- `dataset1_labeled`
- `dataset3_exam_sheet`

### 2.2 支持的文件形式

- `dataset2_question_json`
  - 文件夹中的多个 `.json` 文件
  - 每个文件可以是：
    - 单个题目对象
    - 题目对象数组

- `dataset1_labeled`
  - 文件夹中的多个 `.xlsx` 文件
  - 每个文件需满足双行表头结构

- `dataset3_exam_sheet`
  - 文件夹中的多个 `.xlsx` 文件
  - 每个文件需满足单行字段表头结构

---

## 3. 前端操作方式

1. 使用 `admin / admin123` 登录
2. 进入“导入中心”
3. 选择数据源类型
4. 点击“选择文件夹”
5. 选择本地目录
6. 点击“开始导入”

如果选择的是 `dataset2_question_json`，前端会优先识别目录中的 `.json` 文件。

---

## 4. 后端处理流程

文件夹上传后，后端会按下面的顺序处理：

1. 创建一个新的 `import_batch`
2. 前端按分片把文件批量上传到同一个批次
3. 后端将每个分片中的文件保存到上传目录
4. 逐个文件解析
5. 把所有解析出的记录统一写入同一个批次
6. 对每条记录继续执行归一化
7. 如果是 `dataset2_question_json`，继续调用 `QuestionDedupService`

也就是说，文件夹上传并不是跳过现有流程，而是把“多个文件”并入现有单批次导入链路。

---

## 5. 判重接入位置

对于 `dataset2_question_json` 文件夹导入，判重仍然发生在归一化阶段：

- 外部 ID 命中
- 内容指纹命中
- 疑似重复进入人工复核
- 未命中则新建题目

最终会继续落到这些结果状态之一：

- `CREATED_NEW_QUESTION`
- `MATCHED_BY_EXTERNAL_ID`
- `MATCHED_BY_CONTENT_HASH`
- `PENDING_REVIEW`
- `FAILED`

---

## 6. 坏文件处理策略

当前版本对文件夹批量导入采用“尽量继续导入”的策略：

- 如果某一个文件损坏或格式非法
- 不会让整个文件夹批次直接中断
- 系统会把这个文件记成一条 `FAILED` 记录
- 其他正常文件继续导入

这样更适合大批量导入场景，避免一个坏文件拖垮整个目录。

---

## 7. 批次详情里能看到什么

导入完成后，在“导入中心”批次详情中可以查看：

- 批次状态
- 总记录数
- 新建题目数
- 外部 ID 命中数
- 内容指纹命中数
- 待人工复核数
- 失败记录数
- 每条记录的 `parse_status`
- 每条记录关联到的 `question_id`

如果是文件夹导入，批次的文件标识会显示为：

- `目录名 (N files)`

例如：

- `题目合并 (128 files)`

---

## 8. 当前版本边界

当前版本已经支持：

- 单文件导入
- 文件夹批量导入

当前还没有做的增强项：

- ZIP 压缩包上传
- 超大批次异步后台处理
- 失败文件重试
- 文件级统计报表
- 导入中断 / 取消

---

## 9. 后续建议

如果后面你的 JSON 文件数量非常多，或者单次上传体积很大，下一步建议优先做：

1. 异步批处理
2. 文件级日志
3. 失败重试
4. ZIP 批量上传
