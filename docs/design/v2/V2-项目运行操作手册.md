## 4. 第一步：启动后端

### 4.1 准备后端环境变量

在 `backend/` 目录下创建 `.env` 文件，内容如下：

```env

APP_ENV=local
APP_DEBUG=true
API_V1_PREFIX=/api/v1
DATABASE_URL=mysql+pymysql://root:541521@127.0.0.1:3306/competency_annotation_dev

ENABLE_DOCS=true
```

说明：

- 当前阶段即使 Redis 没启动，后端主服务也可以先跑起来
- 但数据库必须可连接

## 11. 常见问题

### 11.1 后端能启动，但访问题库接口报数据库错误

原因通常是：

- `.env` 中的 `DATABASE_URL` 写错
- MySQL 没启动
- 数据库名不对

请确认：

```env
DATABASE_URL=mysql+pymysql://root:541521@127.0.0.1:3306/competency_annotation_dev
```

### 11.2 终端里 `node` 或 `npm` 找不到

请确认：

- 已安装 Node.js
- 环境变量 `Path` 中包含：

```text
C:\Program Files\nodejs
```

### 11.3 前端能打开，但登录失败

请先确认：

- 后端是否已运行
- 登录接口地址是否正常
- 当前数据库中是否已自动初始化默认开发账号

### 11.4 登录后页面不对

这是角色分流逻辑决定的：

- `admin` 会进管理端首页
- `annotator` 与 `reviewer` 会进用户端工作台

## 13. 导入中心使用方法（2026-04-27 更新）

当前已经支持通过前端“导入中心”上传单个文件。

操作步骤：

1. 先启动后端和前端
2. 用 `admin / admin123` 登录
3. 进入“导入中心”
4. 选择数据源类型
   - `dataset2_question_json`
   - `dataset1_labeled`
   - `dataset3_exam_sheet`
5. 选择一个本地文件
6. 点击“开始导入”

当前行为说明：

- 所有文件都会先生成 `import_batch`
- 原始记录先进入 `source_question_records`
- 如果是 `dataset2_question_json`
  - 会继续进入归一化流程
  - 会调用 `QuestionDedupService`
  - 会将结果标记为：
    - `CREATED_NEW_QUESTION`
    - `MATCHED_BY_EXTERNAL_ID`
    - `MATCHED_BY_CONTENT_HASH`
    - `PENDING_REVIEW`
    - `FAILED`
- 如果是 `dataset1_labeled`
  - 会尝试将题目挂到统一题池
  - 并写入 `question_gold_labels / question_gold_competencies`
- 如果是 `dataset3_exam_sheet`
  - 会尝试将题目挂到统一题池
  - 并写入 `exams / exam_questions / students / student_exam_scores / student_question_responses`

在页面中可以直接看到：

- 批次状态
- 新建题目数
- 外部 ID 命中数
- 内容指纹命中数
- 待人工复核数
- 每条源记录的判重/归一化结果

## 14. 当前支持导入的文件形式

### 14.1 `dataset2_question_json`

当前支持两种 JSON 形式：

1. 单个题目对象

```json
{
  "exerciseID": "Q_001",
  "question": "题干",
  "queAns": "A"
}
```

2. 题目对象数组

```json
[
  {
    "exerciseID": "Q_001",
    "question": "题干1",
    "queAns": "A"
  },
  {
    "exerciseID": "Q_002",
    "question": "题干2",
    "queAns": "B"
  }
]
```

说明：

- 数组里的每个对象都会被当作一条独立题目记录处理
- 当前必填字段是 `exerciseID`
- 推荐同时提供这些字段，归一化效果最好：
  - `question`
  - `queAns`
  - `solution`
  - `subjectCategory`
  - `gradeIndex`
  - `exerciseType`
  - `tags`
  - `queCtlgs`

当前不支持：

- `jsonl` 一行一条 JSON
- 压缩包里的嵌套 JSON 批量上传
- 多层包裹结构但题目数组不在顶层的 JSON

### 14.2 `dataset1_labeled`

当前支持：

- `.xlsx`
- 第一张工作表为数据表
- 需要保持样例中的双行表头结构

表头结构要求：

- 第 1 行包含：
  - `初中题目id`
  - `试题内容`
  - `知识点`
  - `认知层级水平`
  - `核心素养`
- 第 2 行包含：
  - `识记 / 理解 / 应用 / 分析 / 综合 / 评价`
  - `抽象能力 / 运算能力 / 几何直观 / 空间观念 / 推理能力 / 数据观念 / 模型观念 / 应用意识 / 创新意识`

说明：

### 14.4 当前上传功能边界

当前页面上传功能是“单文件上传”，也就是：

- 一次上传一个文件
- 一个文件对应一个导入批次

当前适合：

- 单个 JSON 文件
- 单个 Excel 文件

当前还未正式支持：

- 多文件一次同时上传
- ZIP 压缩包批量导入
- 超大文件异步分片导入

如果后面数据量明显变大，下一步建议升级为：

- 多文件上传
- 异步批处理
- 批次重试
- 失败记录导出

## 15. 疑似重复人工复核页使用方法

当前复核页路由：

- `http://127.0.0.1:5173/dedup-review`

角色约定：

- `reviewer`
  - 主审核角色
- `admin`
  - 兜底和监督角色
- `annotator`
  - 不参与判重合并决策

使用步骤：

1. 用 `reviewer / reviewer123` 或 `admin / admin123` 登录
2. 进入左侧菜单“判重复核”
3. 查看每条候选中的：
   - 新导入记录题干/答案
   - 候选旧题题干/答案
   - 相似度与比较快照
4. 根据实际情况点击：
   - `确认重复`
   - `确认不重复`

动作结果：

- `确认重复`
  - 将当前源记录挂到已有 `question_id`
  - 状态改为 `MATCHED_BY_REVIEW`

- `确认不重复`
  - 为该源记录新建题目
  - 状态改为 `CREATED_BY_REVIEW`

说明：

- 当前后端还没有完整 JWT 权限校验
- 这一版主要依赖前端角色路由控制
- 正式上线前建议补上服务端鉴权

## 16. 文件夹批量导入说明（2026-04-27 更新）

当前“导入中心”除了单文件上传外，已经额外支持“选择整个文件夹批量导入”。
对于文件很多的目录，前端会自动分片上传到同一个批次，避免一次性请求过大导致网络错误。

### 16.1 适用场景

- 一个目录下有很多 `dataset2_question_json` 格式的 `.json` 文件
- 一个目录下有很多同类型的 `.xlsx` 文件，想合并到同一个导入批次

### 16.2 页面操作步骤

1. 使用 `admin / admin123` 登录
2. 进入“导入中心”
3. 先选择数据源类型
4. 点击“选择文件夹”
5. 选择本地目录
6. 点击“开始导入”

系统会把这个目录中的所有匹配文件合并成 **一个导入批次**。

### 16.3 当前支持的文件夹导入形式

- `dataset2_question_json`
  - 支持一个目录下很多 `.json` 文件
  - 每个文件既可以是：
    - 单个题目对象
    - 题目对象数组

- `dataset1_labeled`
  - 支持一个目录下很多 `.xlsx` 文件
  - 每个文件仍需满足双行表头结构

- `dataset3_exam_sheet`
  - 支持一个目录下很多 `.xlsx` 文件
  - 每个文件仍需满足样例中的单行字段表头结构

### 16.4 导入行为说明

- 文件夹中的每个文件都会先被保存到后端上传目录
- 所有解析出的记录会统一写入同一个 `import_batch`
- `dataset2_question_json` 会继续进入：
  - 统一题池归一化
  - `QuestionDedupService` 判重
- 如果某一个文件本身损坏或格式不合法：
  - 不会阻断整个文件夹批次
  - 系统会把这个文件记成一条 `FAILED` 记录
  - 其余文件继续导入

### 16.5 导入结果怎么查看

在“导入中心”批次详情里可以直接看到：

- 批次状态
- 总记录数
- 新建题目数
- 外部 ID 命中数
- 内容指纹命中数
- 待人工复核数
- 失败记录数

如果是文件夹导入，批次文件名会显示为：

- `目录名 (N files)`

例如：

- `题目合并 (128 files)`
