# V2 统一题池与题目判重规则

## 1. 文档目标

本文档用于定义：

- 三类来源数据如何汇总到同一套题目主体系
- 后续重复导入同类数据时，如何判断“是否为同一道题”
- 什么情况可以自动合并
- 什么情况只能给出候选，等待人工复核

本规则服务于后续的归一化导入流水线，适用场景包括：

- 新的 `dataset2_question_json` 类型题库导入
- 新的 `dataset1_labeled` 类型金标准标签导入
- 新的 `dataset3_exam_sheet` 类型考试作答导入

---

## 2. 核心原则

### 2.1 统一题池原则

系统最终只维护一套统一题池：

- `questions` 是题目主表
- 所有来源数据最终都应尽量映射到一个内部 `question_id`
- 不同来源只是补充不同维度的信息，而不是形成三套孤立题库

### 2.2 来源分层原则

三类数据源的角色不同：

- `dataset2_question_json`
  - 主要提供题目主数据
  - 优先决定题目本体内容

- `dataset1_labeled`
  - 主要提供金标准标签
  - 优先补充认知层级与核心素养

- `dataset3_exam_sheet`
  - 主要提供考试和学生作答行为
  - 优先补充考试域数据

### 2.3 判重保守原则

题目判重必须保守处理：

- 宁可少自动合并
- 不要把两道不同题误判为同一道题
- 对高风险场景给出“疑似重复候选”，而不是直接归并

### 2.4 外部映射优先原则

后续增量导入时，最优先使用外部题目映射关系判重：

- `question_external_refs`

这张表是长期增量导入的基础锚点。

## 3. 统一题池结构含义

### 3.1 题目主表

- `questions`
  - 系统内部题目主键
  - 面向标注、推荐、训练、选题

- `question_contents`
  - 题干、答案、解析等内容体

- `question_external_refs`
  - 外部题目编号映射

- `question_catalogs`
  - 题目与教材目录关系

### 3.2 标签补充表

- `question_gold_labels`
  - 金标准标签主记录

- `question_gold_competencies`
  - 金标准核心素养明细

### 3.3 考试行为表

- `exams`
  - 考试主表

- `exam_questions`
  - 考试与题目关系

- `students`
  - 学生主表

- `student_question_responses`
  - 学生作答明细

## 4. 三类来源的合并策略

### 4.1 dataset2_question_json

归一化目标：

- `questions`
- `question_contents`
- `question_external_refs`
- `question_knowledge_points`
- `question_catalogs`

定位：

- 题目主数据来源
- 优先用于建立或更新题目主记录

### 4.2 dataset1_labeled

归一化目标：

- `question_gold_labels`
- `question_gold_competencies`

定位：

- 金标准标签来源
- 不主导题目正文结构
- 优先匹配已有题后补标签

### 4.3 dataset3_exam_sheet

归一化目标：

- `exams`
- `exam_questions`
- `students`
- `student_question_responses`

定位：

- 考试行为来源
- 优先匹配已有题后补考试维度
- 不主导题干与解析等主内容字段

## 5. 题目判重层级

后续导入新数据时，统一按以下顺序判断是否重复。

### 第 1 层：外部 ID 直接命中

判定依据：

- 数据源编码
- 外部题目 ID

查询表：

- `question_external_refs`

规则：

- 如果 `(data_source_id, external_question_id)` 已存在
- 则直接认定为同一道题
- 直接关联到已存在的 `question_id`

这是最高优先级规则。

### 第 2 层：标准化内容哈希命中

如果外部 ID 没命中，则进行内容级判重。

需要对题干与答案做标准化，生成判重指纹：

- `normalized_stem_text`
- `normalized_answer_text`
- `content_hash`

建议哈希输入：

- 标准化题干
- 标准化答案
- 学科
- 题型

如果 `content_hash` 相同，并且学科、题型一致，则高概率可判定为同题。

### 第 3 层：联合字段高置信匹配

如果哈希未命中，则用联合规则做高置信判重：

- 学科一致
- 年级接近或一致
- 题型一致
- 标准化题干高度相似
- 标准化答案一致
- 子题数量一致

此层只建议作为“高置信候选”，默认不要自动合并。

### 第 4 层：疑似重复候选

对于以下情况，只输出疑似候选：

- 题干高度相似，但答案不同
- 题干基本一致，但题型不同
- 同知识点、同模板、不同数值
- 图片变化导致题干不完全一致

此类数据应进入人工复核。

## 6. 标准化规则

为了让后续同类题在不同来源中可对齐，必须有稳定的标准化流程。

### 6.1 题干标准化

标准化建议：

- 去除 HTML 标签
- 统一空白符与换行
- 统一全角/半角符号
- 统一常见数学符号
- 统一选项格式，如 `A.`、`A．`、`A、`
- 图片 URL 和静态资源路径不参与核心题干判重
- 对 MathML / LaTeX 做尽量一致的文本化处理

### 6.2 答案标准化

标准化建议：

- 去除无意义空白
- 统一大小写
- 统一分隔符
- 对多空答案使用稳定的连接方式

### 6.3 指纹生成

建议生成以下字段：

- `normalized_stem_text`
- `normalized_answer_text`
- `content_hash`

可选生成：

- `stem_hash`
- `answer_hash`

### 6.4 推荐阈值

为了让第一版实现更稳定，建议先使用保守阈值：

- `content_hash`
  - 基于 `normalized_stem_text + normalized_answer_text + subject_id + question_type_id`
  - 使用 `sha256`

- `stem_hash`
  - 仅基于 `normalized_stem_text`
  - 用于快速筛候选，不单独作为自动合并依据

- `answer_hash`
  - 仅基于 `normalized_answer_text`
  - 用于辅助确认候选

- `normalized_stem_similarity`
  - 若相似度 `>= 0.98`，可进入高置信候选
  - 若相似度 `< 0.95`，默认不再进入疑似重复候选

- `knowledge_overlap_ratio`
  - 若知识点集合交并比 `>= 0.80`，可作为辅助加分项
  - 不单独作为合并依据

- `grade_distance`
  - 若年级差值 `<= 1`，可视为“接近”
  - 若年级差值 `> 1`，默认不自动合并

说明：

- 第一版不建议引入复杂模型相似度
- 先用规则判重，后续若效果不够再升级为嵌入相似度或学习式判重

## 7. 自动合并规则

### 7.1 可以自动合并的情况

只允许下面两类场景自动合并：

#### 规则 A：外部映射命中

- 已在 `question_external_refs` 中存在同来源同外部 ID

#### 规则 B：内容指纹命中

满足以下全部条件：

- `content_hash` 一致
- 学科一致
- 题型一致

这种情况可以直接归并为已有题。

#### 规则 C：高置信候选命中但不自动合并

满足以下全部条件时，进入 `question_duplicate_candidates`：

- 学科一致
- 题型一致
- `normalized_stem_similarity >= 0.98`
- `answer_hash` 一致或标准化答案一致
- 年级差值 `<= 1`

这种情况默认只生成候选，不直接自动合并。

### 7.2 不自动合并的情况

以下情况一律不自动合并：

- 题干相似但答案不同
- 题干一致但题型不同
- 年级差异明显
- 一个有子题一个无子题
- 图片缺失导致信息不完整
- 知识点完全不一致

## 8. 冲突字段处理策略

同一道题被多个来源命中后，不同字段的处理方式不同。

### 8.1 题目本体字段

字段示例：

- 题干
- 答案
- 解析
- 题型
- 难度

优先级建议：

1. `dataset2_question_json`
2. `dataset3_exam_sheet`
3. `dataset1_labeled`

理由：

- `dataset2` 最像题目主数据
- `dataset3` 主要是考试视角，题目正文只是考试展开形式
- `dataset1` 重点是标签，不是题目结构主来源

### 8.2 可并集字段

字段示例：

- 知识点
- 教材目录
- 外部来源映射

处理方式：

- 做并集
- 不丢失来源

### 8.3 标签字段

字段示例：

- 认知层级
- 核心素养

处理方式：

- 金标准优先写入 `question_gold_labels`
- 不与在线人工标注 `annotations` 混写

## 9. 建议新增的判重支撑结构

为了让判重可持续演进，建议在后续实现时增加一组支撑字段或支撑表。

### 9.1 推荐新增表：`question_dedup_features`

建议字段：

- `id`
- `question_id`
- `normalized_stem_text`
- `normalized_answer_text`
- `content_hash`
- `stem_hash`
- `answer_hash`
- `dedup_version`
- `created_at`
- `updated_at`

作用：

- 统一存放判重特征
- 避免把大量标准化文本塞到 `question_contents`
- 后续升级判重算法时更灵活

### 9.2 推荐新增表：`question_duplicate_candidates`

建议字段：

- `id`
- `source_record_id`
- `candidate_question_id`
- `match_type`
- `confidence_score`
- `comparison_snapshot`
- `review_status`
- `reviewed_by`
- `reviewed_at`

作用：

- 保存疑似重复题候选
- 支撑人工复核

## 10. 判重结果状态建议

建议统一输出以下状态：

- `MATCHED_BY_EXTERNAL_ID`
- `MATCHED_BY_CONTENT_HASH`
- `MATCHED_BY_RULES`
- `CREATED_NEW_QUESTION`
- `PENDING_REVIEW`
- `CONFLICT_DETECTED`

建议补充记录以下元数据：

- `match_score`
- `match_snapshot`
- `dedup_version`

这样后续可以统计：

- 新导入数据中有多少直接命中旧题
- 有多少是新题
- 有多少需要复核

## 11. 三类来源的具体判重策略

### 11.1 新的 dataset2 类型数据

优先规则：

1. 外部 ID 命中
2. 内容哈希命中
3. 联合字段匹配
4. 人工复核

结论：

- 这是后续新建题目主记录的主来源

### 11.2 新的 dataset1 类型数据

优先规则：

1. 先根据外部 ID 对齐题目
2. 对齐不到再尝试内容级匹配
3. 若仍匹配不到，再评估是否需要新建题

结论：

- 该来源优先补标签，不优先主导题目新建

### 11.3 新的 dataset3 类型数据

优先规则：

1. 先匹配已有题
2. 能命中则补考试行为
3. 命不中再尝试内容级新建

结论：

- 该来源优先补考试行为，不优先主导题目正文

---

## 12. 推荐实施顺序

建议分三步落地：

### 第一步：先实现保守版自动判重

- 外部 ID 判重
- 内容哈希判重
- 冲突直接不合并
- 记录判重结果和命中依据

### 第二步：补疑似重复候选

- 建候选表
- 输出高相似候选

### 第三步：补人工复核机制

- 对候选做确认
- 决定是否合并

---

## 13. 最终结论

后续新的三类数据持续导入时，判重规则应当遵循：

1. 先查 `question_external_refs`
2. 再查标准化内容哈希
3. 再做联合字段高置信匹配
4. 拿不准的进入人工复核

系统的最终目标不是维护三套题库，而是：

- 建立一套统一题池
- 用不同来源持续补充题目、标签和考试行为信息

这套判重规则是后续归一化导入流水线的前置规则，也是统一题池可靠性的核心。
