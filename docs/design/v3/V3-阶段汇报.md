# V3 阶段汇报

## 1. 项目定位

本项目是一个面向 K12 多学科题目标注、统一题池治理、主动学习推荐与训练监控的系统。

当前系统采用：

- 后端：`FastAPI + SQLAlchemy + Alembic + MySQL`
- 前端：`React + TypeScript + Vite + Ant Design`
- 架构：单仓库、前后端分离、模块化单体后端

项目的核心目标不是只做一个标注页面，而是逐步建设下面这几条完整链路：

- 原始数据导入
- 统一题池构建
- 题目判重
- 人工标注与聚合
- 推荐与训练
- 管理与可视化

### 2.2 三个数据源的字段并集

按业务域拆解后，字段并集如下。

| 业务域       | 来源字段                                                     |
| ------------ | ------------------------------------------------------------ |
| 题目标识     | `初中题目id`、`exerciseID`、`题目ID`                         |
| 题目正文     | `试题内容`、`question`、`题目内容`、`题干（子题）`           |
| 学科年级     | `subjectCategory`、`测试学科`、`gradeIndex`、`gradeLevel`、`gradeName`、`测试年级`、`年级编号` |
| 题型与难度   | `baseTypeIndex`、`exerciseType`、`blankCount`、`题型标签`、`难度标签` |
| 答案与解析   | `queAns`、`solution`、`题目答案`、`子题答案`                 |
| 知识点与目录 | `知识点`、`tags.*`、`queCtlgs.*`、`知识点标签`、`知识点ID`、`章节标签`、`章节标签ID` |
| 标注标签     | `认知层级水平` 下的 `识记/理解/应用/分析/综合/评价`，`核心素养` 下的 9 个素养列 |
| 题目扩展属性 | `subQueNum`、`subQues`、`has_sub_questions`、图片/MathML/HTML 内容 |
| 考试维度     | `测试时间`、`测试名称`、`测试类型`、`测试总分`、`考试ID`、`考试编号`、`学期` |
| 班级维度     | `测试班级`、`班级编号`、`班级序号`                           |
| 学生维度     | `学生编号`                                                   |
| 作答维度     | `测试得分`、`学生作答`、`题目得分`、`题目分值`               |

### 2.3 并集后的设计原则

基于三范式，不能把上面的字段都堆到 `questions` 一张表里，采用以下拆分原则：

- 题目主数据与考试作答数据分离
- 题目本体与知识点、目录、外部来源、标签结果分离
- 已标注数据与人工标注流程数据分离
- 保留原始导入记录，既支持未来字段扩展，也便于增量同步

### 2.4 统一字段映射结论

| 原始字段域                 | 目标表                                                       |
| -------------------------- | ------------------------------------------------------------ |
| 题目基础属性               | `questions`、`question_contents`                             |
| 外部题目编号与原始 payload | `question_external_refs`、`source_question_records`          |
| 知识点体系                 | `knowledge_points`、`question_knowledge_points`              |
| 教材目录体系               | `catalogs`、`question_catalogs`                              |
| 已有金标准标签             | `question_gold_labels`、`question_gold_competencies`         |
| 考试/班级/学生/作答        | `exams`、`classes`、`students`、`exam_questions`、`student_exam_scores`、`student_question_responses` |
| 系统人工标注               | `annotations`、`annotation_competencies`、`annotation_knowledge_points` |

## 3.4 判重与人工复核

后续增量导入时可能会出现题目重复的问题，因此应当进行判重考虑

判重规则如下：

### 第 1 层：外部 ID 直接命中

判定依据：

- 数据源编码
- 外部题目 ID

查询表：

- `question_external_refs`

规则：

- 如果 `(data_source_id, external_question_id)` 已存在
- 则直接认定为同一道题
- 直接关联到已存在的 `question_id`

这是最高优先级规则。

### 第 2 层：标准化内容哈希命中

如果外部 ID 没命中，则进行内容级判重。

需要对题干与答案做标准化，生成判重指纹：

- `normalized_stem_text`
- `normalized_answer_text`
- `content_hash`

建议哈希输入：

- 标准化题干
- 标准化答案
- 学科
- 题型

如果 `content_hash` 相同，并且学科、题型一致，则高概率可判定为同题。

### 第 3 层：联合字段高置信匹配

如果哈希未命中，则用联合规则做高置信判重：

- 学科一致
- 年级接近或一致
- 题型一致
- 标准化题干高度相似
- 标准化答案一致
- 子题数量一致

此层只建议作为“高置信候选”，默认不要自动合并。

### 第 4 层：疑似重复候选

对于以下情况，只输出疑似候选：

- 题干高度相似，但答案不同
- 题干基本一致，但题型不同
- 同知识点、同模板、不同数值
- 图片变化导致题干不完全一致

此类数据应进入人工复核。

其中：

- 明确命中的题自动归并

- 拿不准的题进入人工复核

- reviewer 进行最终判断

- admin 负责监督与兜底

## 4. 未来工作

### 4.1 第一优先级：标注闭环

下一阶段最优先要完成的是标注主链路闭环：

- 题目领取
- 草稿保存
- 标注提交
- 多人聚合
- 争议复核

这是系统真正从“题库治理平台”走向“标注平台”的关键一步。

### 4.2 第二优先级：导入能力增强

当前导入已完成第一版异步化和大文件进度展示，但距离长期稳定运行还需要继续加强：

- 失败重试
- 断点恢复
- 更完整的批次审计
- 后台任务持久化队列，例如 Celery / Redis
- 服务重启后的任务恢复

这样才能支撑更大规模、长期稳定的数据接入。

### 4.3 第三优先级：复核治理完善

当前 reviewer 可以做复核，但后续还需要：

- 复核日志
- 操作审计
- 错误合并回滚
- 更丰富的候选对比信息

这决定后续统一题池是否能长期稳定维护。

### 4.4 第四优先级：训练与推荐

在统一题池、判重和标注稳定后，下一阶段要推进：

- 推荐策略接入
- 训练任务接入
- 训练结果回写
- 可视化监控

这部分将决定系统是否能真正形成“主动学习 + 标注 + 训练”的闭环。

### 4.5 第五优先级：上线前安全与工程化

当前版本属于开发可运行版，距离生产可用仍有差距。

后续要补的内容包括：

- 密码加密存储
- 更严格的服务端权限校验
- 上传安全策略
- 更完善的异常处理
- 日志、监控、回滚策略
