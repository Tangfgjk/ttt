# V3 项目总览与阶段进度

更新时间：`2026-05-10`

## 1. 文档目的

本文件用于站在项目全局视角，对当前系统的真实进度做阶段性总结，回答四个核心问题：

- 已经做完了什么
- 当前系统已经能稳定运行到什么程度
- 还有哪些关键能力尚未完成
- 下一阶段应该把重点放在哪里

## 2. 当前项目定位

当前项目已经不再是早期“统一题池 + 判重 + 页面联调”的原型系统，而是进入了：

**V4.10 主动学习训练闭环与题池治理联调阶段**

当前已经形成的主链路包括：

- 多源题库导入
- 统一题池归一化
- 自动判重与人工复核
- 标注员培训准入与学段限制
- 普通标注、多人聚合与分歧复核
- 试题嵌入补全与可视化
- 主动学习训练、预测选题、CoreSet 选题
- 训练监控、模型版本管理、题池回收与批次撤回

这意味着当前系统已经从“功能拼装”推进到了“闭环可跑 + 基础治理可用”的阶段。

## 3. 已完成内容概览

### 3.1 基础底座

- FastAPI、SQLAlchemy、Alembic、MySQL 本地联调稳定
- 统一配置与主路由组织完成
- 登录与角色分流已接通

### 3.2 导入与统一题池

- 支持多种原始数据导入
- 统一题池支持筛选、分页、详情抽屉、来源映射查看
- 导入、归一化、题目内容与外部映射链路已打通

### 3.3 判重与复核

- 自动判重规则落地
- 疑似重复人工复核落地
- 系统管理员可按相似度阈值批量确认重复

### 3.4 标注闭环

- 标注员培训准入落地
- 培训范围与学段限制落地
- 题目领取、锁定、提交、多人聚合、分歧复核落地
- 状态流转已形成：
  - `PENDING`
  - `WAITING`
  - `IN_PROGRESS`
  - `REVIEW_PENDING`
  - `COMPLETED`

### 3.5 试题嵌入与可视化

- 试题 embedding 补全与重建
- PCA / UMAP / 随机投影等降维展示
- 可视化与统一题池跳转联动
- 可视化查询与图表渲染性能优化

### 3.6 主动学习训练闭环

- 训练任务创建与后台 worker 执行
- 初中 / 高中训练学段切换
- 合并金标训练
- 模型版本保存、激活与切换
- 低置信度预测选题
- CoreSet 代表性选题
- GPU worker 分离
- 同数据同参数下训练可复现

### 3.7 训练监控与治理能力

- 训练任务表、模型版本表、预测任务表
- 模型指标趋势图
- 任务与模型双向关联
- 训练日志、真实 batch 级预测进度、预测取消
- 系统管理员题池查看、题池回收与按批次撤回选题

### 3.8 开发联调支持

- 默认管理员、标注员、复核员账号
- 新增 3 个开发标注员账号
- 新开发标注员默认未通过培训，可直接进入培训流程联调

## 4. 当前系统已经具备的能力

截至目前，系统已经可以完成：

1. 启动前后端并正常访问
2. 使用不同角色登录
3. 导入题库并形成统一题池
4. 执行自动判重与人工复核
5. 执行标注员培训与学段限制控制
6. 完成普通标注、聚合与复核
7. 生成题目 embedding 并在可视化页查看分布
8. 训练主动学习模型并生成模型版本
9. 运行低置信度预测选题与 CoreSet 选题
10. 在训练监控页查看训练、模型、预测与趋势
11. 回收题池并撤回某次选题批次

## 5. 当前仍待加强的部分

虽然当前闭环已经能跑，但仍有几个方向需要继续加强：

### 5.1 正式评估模式尚未建立

当前更偏工程可运行，并非严格实验评估模式。仍需补齐：

- 固定测试集
- 五折交叉验证或重复实验
- 更正式的模型对比与效果报告入口

### 5.2 大规模候选池下的性能优化仍需推进

当前已支持全量未标注预测与更大范围 CoreSet，但在题量继续增大后，仍需继续优化：

- 全量未标注预测速度
- 全池 CoreSet 性能
- 分层筛选、批处理与缓存策略

### 5.3 治理能力仍是初版

虽然已有题池回收和批次撤回，但仍可继续补齐：

- 更细粒度的审计日志
- 批次备注与管理
- 更丰富的模型版本治理能力
- 更稳的失败恢复与重试能力

### 5.4 上线前安全与运维准备尚未完成

当前版本仍属于开发联调用版本，还没有收口为正式生产版本：

- 密码仍需加密存储
- 权限仍需更严格收口
- 运行监控、告警与备份策略仍需建立

## 6. 当前阶段结论

截至 `2026-05-10`，项目已经完成了从“统一题池联调”到“主动学习训练闭环 + 基础治理联调”的关键跃迁。

如果用阶段划分来描述：

- `V1-V3`：底座、统一题池、导入、判重、标注基础链路
- `V4.5-V4.10`：可视化、训练闭环、监控、治理能力补齐
- `V5`：正式进入性能优化、正式评估、上线前治理与系统化增强阶段

因此，后续开发建议明确切换到：

**V5 阶段开发**

其核心目标不再是“补基础功能”，而是：

- 提升稳定性
- 提升性能
- 建立正式评估能力
- 完善治理与上线准备
