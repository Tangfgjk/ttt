# V3 项目总览与阶段进度

## 1. 文档目的

本文件用于在 V1 设计基线、V2 实施基线的基础上，给出项目截至当前阶段的真实状态，明确：

- 已经做完了什么
- 当前系统已经能运行到什么程度
- 还有哪些关键能力没有完成
- 后续优先级应该如何排序

## 2. 项目当前定位

当前项目已经不是纯设计文档阶段，也不是只有数据库和骨架的空壳阶段，而是一个已经具备以下能力的“可运行中期版本”：

- 后端可启动
- 前端可启动
- MySQL 表结构与 Alembic 迁移已落地
- 多类型数据导入已接通
- 统一题池已形成
- 判重与人工复核链路已打通
- 统一题池页面已经能进行筛选、分页、详情查看

当前更准确的阶段判断是：

- 阶段名称：`V3 可运行联调阶段`
- 当前核心方向：`统一题池治理 + 标注闭环完善 + 导入能力增强`

## 3. 已完成工作总览

### 3.1 设计与文档基线

- 已将用户提供的 5 份原始系统设计文档归档到 `docs/design/v1`
- 已输出 V1 分析总览文档
- 已完成 V2 实施设计文档
- 已完成 V2 数据库表结构、模块接口、API 清单、目录结构和第一阶段任务拆分
- 已完成 V2 统一题池与判重规则文档
- 已完成 V2 运行操作手册与前端方案文档

### 3.2 数据库与后端底座

- MySQL 初始表结构已设计并执行到本地数据库 `competency_annotation_dev`
- Alembic 初始迁移已建立并实际落库
- 表与字段注释已补齐
- 后端基础骨架已搭建完成：
  - `FastAPI`
  - `SQLAlchemy`
  - `Alembic`
  - 配置管理
  - 路由组织
  - MySQL 连接

### 3.3 认证与角色体系

- 已接通真实登录接口
- 当前支持基于数据库的角色分流
- 已有开发账号自动初始化
- 当前角色分工已经明确：
  - `admin`
  - `annotator`
  - `reviewer`

说明：
- 按当前需求，开发阶段密码仍为明文存储与明文比对
- 这一点后续上线前必须收口为加密存储

### 3.4 原始导入与批次管理

已支持以下三类数据导入：

- `dataset1_labeled`
- `dataset2_question_json`
- `dataset3_exam_sheet`

当前导入能力已经包括：

- 单文件上传导入
- 文件夹批量导入
- 大量 JSON 文件分片上传
- 导入批次管理
- 原始记录落库到 `source_question_records`
- 批次统计、状态展示、失败记录保留

### 3.5 统一题池与归一化导入

当前统一题池主链路已经具备实际效果，不再是纸面设计。

已完成：

- `dataset2_question_json -> questions / question_contents / question_external_refs / question_knowledge_points / question_catalogs`
- `dataset1_labeled -> question_gold_labels / question_gold_competencies`
- `dataset3_exam_sheet -> exams / exam_questions / students / student_exam_scores / student_question_responses`

这意味着三类来源数据已经不再只是原始落库，而是能够进入正式业务表结构。

### 3.6 判重服务与人工复核

已完成：

- 统一题池判重规则落地
- `QuestionDedupService` 实现
- 判重支撑表落地：
  - `question_dedup_features`
  - `question_duplicate_candidates`
- 支持结果：
  - `MATCHED_BY_EXTERNAL_ID`
  - `MATCHED_BY_CONTENT_HASH`
  - `PENDING_REVIEW`
  - `CREATED_NEW_QUESTION`

已完成人工复核链路：

- reviewer 角色可查看疑似重复候选
- reviewer 可确认重复
- reviewer 可确认不重复
- admin 可作为监督与兜底角色查看复核结果

### 3.7 前端工程与页面联调

前端工程已从“空骨架”推进到“可联调页面”阶段。

已完成：

- `React + TypeScript + Vite + Ant Design` 前端工程
- 登录页与角色分流
- 项目总览页
- 导入中心页
- 统一题池页
- 判重复核页
- 标注工作台基础页骨架

统一题池页当前已支持：

- 总题量统计
- 筛选条件
  - 学科
  - 年级
  - 题型
  - 标注状态
  - 关键词
- 分页浏览
- 每页条数切换
- 题目详情抽屉
- 渲染视图 / 原始文本切换
- 列表行展开预览完整题干

## 4. 当前系统已具备的可用能力

从“功能可用性”角度看，当前系统已经可以完成以下事情：

1. 启动前后端并正常访问系统
2. 使用不同角色登录系统
3. 将三类数据文件导入系统
4. 形成统一题池
5. 对题目执行自动判重
6. 对疑似重复题执行人工复核
7. 在前端统一题池中查看题目、筛选题目和分页浏览题目

## 5. 尚未完成但已明确的任务

### 5.1 标注闭环尚未完成

虽然标注工作台已经有页面骨架，但完整业务闭环还未完成。

待完成：

- 题目领取
- 草稿保存
- 标注提交
- 多人聚合
- 争议复核
- 标注历史记录

### 5.2 异步导入与失败重试尚未完成

当前导入已经可用，但还不够“生产级”。

待完成：

- 导入异步任务化
- 失败记录重试
- 批次中断恢复
- 更细粒度的导入审计

### 5.3 复核审计与回滚尚未完成

当前 reviewer 能做复核，但审计和回滚机制还不完善。

待完成：

- 复核结果审计日志
- 错误合并回滚
- 复核操作人追踪

### 5.4 推荐、训练、可视化仍属于下一阶段

当前这些模块已有设计和页面入口，但还没有真正打通业务闭环。

待完成：

- 推荐策略与推荐批次真实联调
- 训练任务创建、执行与状态回写
- 可视化页真实数据驱动
- 主动学习闭环验证

### 5.5 安全性与上线准备未完成

当前版本是开发可用版本，不是生产可用版本。

待完成：

- 密码加密存储
- 更严格的后端权限校验
- 文件上传安全策略
- 更完整的异常处理与监控

## 6. 当前优先级建议

建议下一阶段按下面顺序推进：

### 第一优先级

- 打通标注提交闭环
- 让标注员真正完成一题从领取到提交的流程

### 第二优先级

- 将导入能力升级为更稳的异步批处理
- 补齐失败重试与审计

### 第三优先级

- 补齐题目详情中的更多业务信息
  - gold label
  - 考试作答摘要
  - 导入批次信息

### 第四优先级

- 推荐、训练、可视化模块进入真实联调

## 7. 当前阶段结论

截至当前版本，项目已经完成了从“设计方案”到“可运行、可导入、可浏览、可复核”的关键跨越。

当前最重要的判断不是“是否还有很多页面没做”，而是：

- 统一题池已经建立
- 导入与判重已经成链
- 前端已经能看见真实数据

这说明项目的基础主干已经成立。

接下来真正决定项目质量的，不再是继续补底座，而是：

- 标注闭环能否打通
- 导入与复核是否足够稳定
- 推荐、训练、可视化能否建立第二阶段能力
