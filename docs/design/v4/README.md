# V4 设计与演进文档

## 1. 目录定位

`v4/` 目录用于承接统一题池基础能力完成之后的第二阶段建设，重点不再是“页面可见”本身，而是把真正影响系统上限的几条主链路做深做稳：

- 标注员培训准入与学段隔离
- 试题嵌入与可视化治理
- 主动学习训练闭环
- 训练监控与模型版本治理
- 题池回收、批次撤回与系统管理员治理能力

到 `V4.10` 为止，V4 阶段的关键联调能力已经基本闭合，后续将进入 `V5` 阶段开发。

## 3. V4 阶段收束结论

截至 `2026-05-10`，V4 阶段已经完成以下几类关键建设：

- 统一题池、导入、判重、人工复核主链路跑通
- 标注员培训准入、学段限制、多人标注聚合与分歧复核落地
- 试题嵌入补全、嵌入可视化、统一题池联动与缓存优化落地
- 主动学习训练、预测选题、CoreSet 选题、模型版本与训练监控落地
- GPU worker、训练可复现性、预测取消与真实 batch 级进度落地
- 系统管理员题池回收、按批次撤回选题、开发账号补齐等治理能力落地

因此，V4 后续不再作为“主开发阶段”，而是作为 `V5` 的稳定基础版本。

## 4. V5 起点建议

进入 `V5` 后，建议把重点从“闭环是否存在”转向“闭环是否足够稳定、足够高效、足够可评估”：

- 建立正式评估模式：固定测试集、交叉验证或重复实验
- 优化全量候选池下 CoreSet 与低置信度预测的性能
- 补齐更完整的审计、回滚、失败恢复与任务治理能力
- 完善上线前安全、权限与运维准备
