# V4.10 题池治理与开发账号完善总结

更新时间：`2026-05-10`

## 1. 本轮目标

本轮工作主要围绕系统管理员治理能力和开发联调便利性展开，目标是把当前已经打通的主动学习闭环进一步补齐“收回、撤回、重选、重跑”的管理能力，为后续 `V5` 阶段开发做准备。

## 2. 完成内容

### 2.1 登录页开发账号补齐

登录页开发账号展示区已补充以下账号：

- `admin / admin123`
- `annotator / annotator123`
- `annotator_dev_1 / annotator123`
- `annotator_dev_2 / annotator123`
- `annotator_dev_3 / annotator123`
- `reviewer / reviewer123`

其中新增的 3 个开发标注员账号初始均设置为：

- 角色：`annotator`
- 培训范围：`none`
- 培训状态：未通过培训

首次登录会进入标注员培训页面。

### 2.2 默认账号自动补齐逻辑增强

后端默认账号初始化逻辑已从“仅在空库时初始化”调整为“每次登录时确保默认账号存在”，这样在开发联调过程中，即使数据库已有部分用户，也能继续自动补齐缺失的默认账号。

### 2.3 管理后台题池治理能力补齐

管理后台新增题池治理区域，系统管理员现在可以：

- 点击未标注池、待标注池、领取锁定池、待复核池、已标注池卡片
- 直接跳转到统一题池查看对应状态的题目列表
- 一键回收领取中的题目与待标注池中的题目
- 查看最近选题批次
- 按批次撤回某次 `CoreSet` 或 `低置信度预测选题`

### 2.4 题池回收能力

新增题池回收接口，支持：

- 将 `IN_PROGRESS` 且尚未实际产生标注结果的题目收回
- 将 `WAITING` 且尚未开始标注的题目退回到 `PENDING`

这使得管理员可以在重新规划选题策略时，先把题目从领取中/待标注状态回收到未标注池，然后重新执行 `CoreSet` 或低置信度选题。

### 2.5 选题批次撤回能力

新增按批次撤回能力，支持对历史选题批次执行回收：

- 支持批次类型：
  - `CoreSet` 选题
  - 低置信度预测选题
- 撤回效果：
  - 收回本批次仍处于 `IN_PROGRESS` 的题目
  - 将本批次仍处于 `WAITING` 的题目退回 `PENDING`

这意味着管理员可以撤销一次不满意的选题结果，而不必手动逐题处理。

## 3. 当前联调状态

截至本轮完成后，系统在主动学习闭环方面已经具备以下管理能力：

- 训练模型
- 低置信度预测选题
- CoreSet 代表性选题
- 预测任务取消与真实进度显示
- 训练过程日志与模型版本追踪
- 题池查看
- 题池统一回收
- 按批次撤回选题

这使得当前系统不再只是“能选题、能训练”，而是具备了初步的“可治理、可回收、可重跑”能力。

## 4. 对 V5 的意义

`V4.10` 可以视为 `V4` 阶段的一个收束版本。它的意义不在于新增了某个孤立页面，而在于为 `V5` 阶段提供了更稳定的开发起点：

- 题池状态可以重置，不再担心联调后题目卡死在中间状态
- 选题批次可以撤回，便于不断试验不同策略
- 开发标注员账号补齐，便于多人并行联调
- 登录入口展示更完整，减少开发环境口口相传的成本

## 5. 下一阶段建议

建议后续 `V5` 阶段重点转向以下几个方向：

1. 正式评估模式建设  
   包括固定测试集、五折交叉验证或重复实验能力。

2. 全量候选池性能优化  
   包括全量未标注数据下低置信度预测和全量题池下 CoreSet 的效率优化。

3. 更细粒度治理能力  
   包括任务审计、失败恢复、批次备注、模型回滚与策略对比。

4. 上线前准备  
   包括密码加密、权限收口、运行监控与运维治理。

## 6. 结论

`V4.10` 标志着当前系统已经从“功能联调阶段”进一步推进到“具备基础治理能力的联调阶段”。  
后续 `V5` 可以不再围绕基础功能补洞，而是围绕稳定性、性能、评估与上线准备展开系统化建设。
