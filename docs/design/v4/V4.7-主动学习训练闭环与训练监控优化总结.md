# V4.7 主动学习训练闭环与训练监控优化总结

记录日期：2026-05-10

## 1. 本轮目标

本轮工作围绕“主动学习训练闭环可用、可复现、可管理”三条主线展开，主要解决了以下问题：

1. 训练样本筛选与“合并金标”开关不一致，导致界面显示有样本但训练实际为 0。
2. 训练学段固定为初中，无法切换高中。
3. GPU 训练环境与后端 Web 服务环境解耦不清晰，界面选择 GPU 后无法稳定落到可用 CUDA 环境。
4. 训练完成后模型版本落库失败，`model_versions` 表与 ORM 字段不一致。
5. 相同数据、相同参数多次训练结果不一致，缺少完整随机性控制。
6. 训练监控页可读性不足，任务、模型、趋势图之间的关联不清晰。

## 2. 训练闭环功能修复

### 2.1 合并金标开关修复

前端原先的“合并金标”开关没有稳定纳入训练提交参数，导致界面看似打开，但后端收到的仍可能是 `include_gold_labels=False`。

本轮调整后：

1. 前端改为显式本地状态控制开关。
2. 提交训练请求时强制携带当前 `include_gold_labels` 值。
3. 开关状态持久化到浏览器 `localStorage`。

结果：

- `junior + include_gold_labels=True` 可训练样本恢复为 `323`
- `senior + include_gold_labels=True` 可训练样本恢复为 `280`

### 2.2 新增训练学段选择

主动学习训练参数原先只允许：

```text
target_stage = "junior"
```

现已扩展为：

```text
target_stage = "junior" | "senior"
```

前端训练表单新增“训练学段”下拉，默认仍为“初中”。

## 3. GPU Worker 方案落地

### 3.1 背景

项目当前后端主环境 `backend/.venv` 安装的是 CPU 版 PyTorch，不适合直接承担 GPU 训练；但本地已存在可用 CUDA 环境。

### 3.2 方案

采用“Web 服务环境”和“GPU 训练环境”分离的方案：

1. 后端主服务仍可使用当前 Web 环境。
2. 训练 worker 根据设备选择单独 Python 解释器。
3. 选择 `device=cuda` 时，优先使用 `ACTIVE_LEARNING_GPU_WORKER_PYTHON`。

相关配置：

```text
ACTIVE_LEARNING_WORKER_PYTHON=
ACTIVE_LEARNING_GPU_WORKER_PYTHON=D:/anaconda3/envs/ttt_gpu311/python.exe
```

### 3.3 新 GPU 环境

本轮新建了 `Python 3.11` 的 GPU worker 环境：

```text
D:/anaconda3/envs/ttt_gpu311/python.exe
```

环境验证通过：

```text
torch 2.3.1+cu121
torch.cuda.is_available() == True
GPU: NVIDIA GeForce RTX 3060
```

## 4. 模型类型识别与模型版本落库修复

### 4.1 真实模型类型确认

虽然项目中曾使用“Math Roberta MLM”这一命名，但实际本地模型配置为：

```text
model_type = "bert"
architectures = ["BertForMaskedLM"]
tokenizer_class = "BertTokenizer"
```

运行时加载结果也确认是：

```text
BertConfig
BertTokenizerFast
BertModel
```

因此当前基础模型真实类型为 `BERT`，不是 `RoBERTa`。

### 4.2 model_versions 落库失败修复

数据库 `model_versions` 表中存在以下字段：

- `model_type`
- `base_model_name`
- `artifact_path`
- `metrics_json`

而旧代码中的 `ModelVersion` ORM 未完全映射，导致训练已完成但模型版本写库时报错：

```text
Field 'model_type' doesn't have a default value
```

本轮修复内容：

1. ORM 补齐数据库真实字段。
2. 训练完成后自动从 `AutoConfig` 读取 `model_type`。
3. 一并保存 `base_model_name`、`artifact_path`、`metrics_json`。

结果：

- checkpoint 保存成功
- 模型版本落库成功
- 后续切换到其他基础模型时，`model_type` 可以自动跟随

## 5. 训练可复现性修复

### 5.1 发现的问题

同样的 `323` 条样本、同样参数、同样随机种子，多次训练得到的结果不同。

排查后确认原因不是“接着前一个模型继续训练”，而是：

1. 训练/验证切分虽固定，但训练过程的随机性未完全固定。
2. 分类头每次重新随机初始化。
3. DataLoader 训练顺序随机打乱。
4. Dropout 存在随机行为。
5. GPU 算子存在非确定性。
6. 更关键的是，基础模型加载时 `pooler` 层会有新随机初始化，而旧版代码在这一步之后才设置随机种子。

### 5.2 修复措施

本轮已补齐以下可复现控制：

1. 使用 `random_seed` 固定 `random / numpy / torch / torch.cuda`
2. 开启 `torch.use_deterministic_algorithms(True)`
3. 设置：
   - `torch.backends.cudnn.deterministic = True`
   - `torch.backends.cudnn.benchmark = False`
   - 禁用 TF32
4. 为训练 DataLoader 使用固定种子的 `Generator`
5. 为 worker 环境设置：

```text
CUBLAS_WORKSPACE_CONFIG=:4096:8
```

6. 最关键的一步：在 `AutoModel.from_pretrained(...)` 之前就进入确定性模式，确保基础模型加载阶段的随机初始化也固定下来

### 5.3 当前结果

经 CPU 和 GPU 两条链路验证：

- 同样数据
- 同样参数
- 同样随机种子
- 同样运行环境

多次独立训练结果已经一致。

## 6. 模型命名与任务-模型关联优化

### 6.1 原问题

旧版界面中：

- 训练任务使用 `train_20260510075402_...`
- 模型版本使用 `M0 / M1 / M2...`

管理者无法快速对应“哪个模型由哪个任务训练生成”。

### 6.2 本轮优化

后端在 overview 输出中补充：

1. 训练任务的可读名称
2. 模型版本的可读名称
3. 训练任务关联的模型版本
4. 模型版本关联的来源训练任务
5. 样本量、模型类型、基础模型名、参数摘要

### 6.3 新命名策略

新生成的模型版本不再只用 `M3` 这类简单编号，而是按以下维度编码：

- 学段
- 模型类型
- 数据集样本量
- 训练轮数
- batch size
- learning rate
- max length
- 是否合并金标
- 时间戳

旧版本数据不改数据库原值，但前端会展示为更可读的摘要名。

## 7. 训练监控页优化

### 7.1 表格能力增强

训练任务表和模型版本表均已补充 `Detection` 指标列。

训练任务详情中新增：

1. 数据集大小
2. 训练/验证样本数
3. 生成模型
4. 基础模型类型
5. 参数设置摘要
6. 趋势分组信息
7. epoch 明细

模型版本表新增：

1. 来源任务
2. 样本量
3. Detection
4. 查看任务入口

### 7.2 趋势图逻辑修正

旧版趋势图是“每有一个模型版本就画一个点”，这会把同参数、同数据量的重复训练也都画进去，不利于观察“随着数据集增加的趋势变化”。

本轮已调整为：

1. 按“模型 + 学段 + 参数设置”分组
2. 同组下如果是同一数据集规模的重复训练，只保留一个趋势点
3. 管理者可以选择不同分组查看趋势

当前的趋势图更适合回答：

```text
在同一类模型、同一组参数设置下，随着数据量增加，Accuracy / Macro-F1 / Detection 如何变化？
```

## 8. 训练页界面优化

根据管理使用体验，本轮又对训练页界面做了一轮整理：

1. 所有主要文案改回中文
2. 训练任务表改为分页展示，避免全部铺开
3. 模型版本与预测任务由并列布局改为上下布局
4. 趋势分组说明改为中文摘要，降低阅读负担

## 9. 当前状态总结

截至本轮，主动学习训练闭环已经具备以下能力：

1. 可在初中/高中范围内选择训练学段
2. 可稳定启用“合并金标”参与训练
3. 可按 CPU / GPU 选择训练设备
4. GPU 训练链路已经打通
5. 训练完成后可稳定生成 checkpoint 与模型版本
6. 同样数据与参数下训练结果已可复现
7. 训练任务、模型版本、趋势图之间的关联关系已经清晰化
8. 趋势图开始具备按参数分组观察数据规模变化趋势的能力
