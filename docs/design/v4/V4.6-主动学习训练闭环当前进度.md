## 1. 当前阶段结论

当前系统已经从“核心集选题原型”推进到“可运行的主动学习训练闭环联调”阶段。

已经打通的主链路包括：

1. 从未标注池中选题进入待标注池。
2. 使用已完成题目和金标题目形成训练样本。
3. 基于本地 `math_mlm_model` 启动能力维度分类训练。
4. 训练成功后生成模型版本和 checkpoint。
5. 模型版本可用于低置信度预测选题。
6. 管理后台可查看训练进度、训练日志，并可手动结束训练任务。

当前仍处于联调阶段，重点风险在训练性能、CUDA 环境、训练任务中断恢复和模型指标验证。

## 3. 训练数据实际来源

管理后台的“可训练样本数”展示的是已完成题目的业务池数量，但训练任务实际取样更严格。

训练样本来源有两类：

1. `QuestionLabelAggregate`
   人工标注和复核后汇总出的聚合标签。
2. `QuestionGoldLabel`
   导入或预置的金标标签，需要在训练表单中打开“合并金标”。

当前数据库检查结果：

```text
已完成题目：603
初中阶段且有题干：323
有聚合标签的训练样本：0
有金标标签的题目：323
```

因此：

- 不打开“合并金标”时，训练样本数为 0，会失败。
- 打开“合并金标”后，可以使用 323 道初中金标题训练。
- 当前训练参数 `val_size=0.2` 时，323 道被切分为 258 道训练、65 道验证。

表单中的 `min_train_samples` 已改名为“最小训练样本数”，避免误解为实际训练样本总量。

## 4. 管理后台训练能力

管理后台已经补齐以下训练控制能力：

- “合并金标”开关持久化到浏览器 `localStorage`，刷新后保留上次手动选择。
- 新增“训练设备”选择：自动、CPU、GPU。
- 新增“结束训练”按钮，可终止正在运行的训练 worker。
- 开始训练按钮在已有训练运行时禁用，避免重复启动。
- 训练进度下方新增“训练控制台”，每 2 秒刷新训练日志。

训练日志接口：

```text
GET /api/v1/active-learning/training-runs/{run_id}/logs
```

结束训练接口：

```text
POST /api/v1/active-learning/training-runs/{run_id}/cancel
```

训练日志文件：

```text
backend/logs/training_run_<run_id>.log
```

训练 worker pid 文件：

```text
backend/logs/training_run_<run_id>.pid
```

如果任务是在 pid 文件机制上线前启动的，后端会兜底按 `active_learning_worker training <run_id>` 命令行搜索进程。

## 6. 当前限制与风险

### 6.1 CPU 训练过慢

当前 PyTorch 为 CPU 版，日志显示：

```text
Model loaded on device=cpu.
```

即使只训练分类头，Bert/RoBERTa 前向也需要经过 backbone，因此每个 batch 仍然较慢。

建议后续改进：

- 安装 CUDA 版 PyTorch。
- 在 GPU 可用时将训练设备选择为 GPU。
- 若仍需 CPU 运行，可降低 `max_length`、`batch_size` 或 `epochs` 做快速联调。

### 6.2 当前人工聚合标签为 0

目前能训练主要依赖金标题。人工标注闭环若要真正反哺模型，需要稳定产出 `QuestionLabelAggregate`。

后续应检查：

- 标注提交后是否进入复核。
- 复核通过后是否生成聚合标签。
- 聚合标签是否覆盖训练需要的 9 个初中能力维度。

### 6.3 训练任务状态恢复仍需增强

已支持手动结束训练，但如果用户直接关闭后端、关闭电脑或杀进程，数据库可能仍残留 `RUNNING`。

后续建议：

- 后端启动时扫描 `RUNNING` 训练任务。
- 若 pid 不存在，则自动标记为 `FAILED` 或 `INTERRUPTED`。
- 前端可显示“疑似中断”状态。

### 6.4 GPU 选择需要环境配套

前端已经可以选择 GPU，但后端会严格检查 `torch.cuda.is_available()`。

如果当前环境仍为 `torch 2.2.2+cpu`，选择 GPU 会失败并提示：

```text
CUDA was selected but is not available.
```

这是预期保护，避免用户以为已经使用 GPU，实际仍在 CPU 上训练。

## 7. 下一步建议

优先级建议如下：

1. 安装并验证 CUDA 版 PyTorch，确认训练日志显示 `device=cuda`。
2. 跑完 323 道金标题训练，生成首个模型版本。
3. 用首个模型版本执行低置信度预测选题。
4. 将选中题目推入待标注池，走人工标注和复核。
5. 打通复核结果到 `QuestionLabelAggregate` 的稳定回流。
6. 再用“聚合标签 + 金标”训练下一版模型。
7. 对比每轮模型版本的 Accuracy、Macro-F1、Detection 指标变化。

当前最短可验证路径：

```text
合并金标 -> CPU/GPU 训练 -> 生成 M0 -> 低置信度预测选题 -> 入待标注池
```
