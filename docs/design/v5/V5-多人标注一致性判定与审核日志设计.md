# V5 多人标注一致性判定与审核日志设计

更新时间：`2026-05-11`

## 1. 背景

项目在 `V4.10` 阶段已经完成了统一题池、三人标注、争议复核、训练闭环和题池治理等基础联调能力。  
进入 `V5` 后，需要把多人标注能力从“可以跑通”提升为“规则清晰、过程可追踪、争议可治理、复核可闭环”。

本设计文档用于明确以下问题：

- 多人标注时每道题如何计票
- 初中 9 个核心素养和对应层级如何参与一致性判断
- 什么叫做一致，什么叫做分歧
- 分歧后由谁处理、如何处理
- 管理员和复核员如何查看审核日志与操作历史
- 争议题如何自动流转给复核员并锁定一致维度

## 2. 业务定义

### 2.1 标注人数要求

- 每道题默认至少需要 `3` 名标注员完成标注
- `required_annotations` 用于表示当前题目需要的标注人数
- 当前默认设计以 `3` 人收敛为主，争议题优先通过复核员闭环，不再依赖管理员手动打回补票

### 2.2 核心素养层级定义

以初中数学为例，标注维度包含 `9` 个核心素养，每个核心素养都需要标记层级：

- `0`：该题不体现该核心素养
- `1`：体现较弱
- `2`：体现中等
- `3`：体现较强

这里必须明确：

- 默认值就是 `0`
- 标注员只需要修改自己认为“有体现”的素养维度
- 未修改的维度按 `0` 参与正式计票

因此，在本系统中：

- `0` 不是空值
- `0` 不是漏填
- `0` 是一张有效票，表示“无此素养”

### 2.3 一致性判断单位

系统不是把整道题看作一票，而是按“维度”逐个判断。

维度包含：

- `认知层级`
- 每一个核心素养维度

也就是说，某道题的 3 人标注结果，会拆成多个独立投票面：

- 认知层级投票面
- 核心素养 A 投票面
- 核心素养 B 投票面
- …

## 3. 一致性算法

## 3.1 维度级判定规则

对任意一个维度，系统统计 3 名标注员给出的层级值，包括 `0/1/2/3`。

判定规则如下：

- `3/3` 相同：`UNANIMOUS`
- `2/3` 相同：`MAJORITY`
- `1/1/1`：`DISPUTED`

例如：

### 示例 1：多数一致

- 标注员 A：`0`
- 标注员 B：`2`
- 标注员 C：`2`

结论：

- 该维度两票为 `2`
- 一票为 `0`
- 结果为 `MAJORITY`
- 推荐层级为 `2`

### 示例 2：完全一致

- 标注员 A：`0`
- 标注员 B：`0`
- 标注员 C：`0`

结论：

- 结果为 `UNANIMOUS`
- 推荐层级为 `0`

这意味着三位标注员都认为该题不体现这个素养。

### 示例 3：无多数分歧

- 标注员 A：`0`
- 标注员 B：`1`
- 标注员 C：`2`

结论：

- 三票完全分散
- 结果为 `DISPUTED`
- 该维度不能自动收敛

## 3.2 题目级判定规则

题目是否可以自动完成，不取决于某一个维度，而取决于全部维度是否都能收敛。

规则如下：

1. 如果已完成标注人数 `< required_annotations`  
   题目仍未结束，继续等待后续标注

2. 如果所有维度都至少达到 `MAJORITY`  
   题目自动聚合，进入 `COMPLETED`

3. 只要有任意一个维度是 `DISPUTED`  
   题目进入 `REVIEW_PENDING`

换句话说：

- 维度级允许 `2/3` 多数通过
- 题目级要求“所有维度都至少有多数”

## 3.3 一致率计算

系统为每个维度和整道题都计算一致率。

### 维度一致率

公式：

`agreement_score = 该维度最高票数 / 该维度总票数`

示例：

- `2,2,2` -> `3/3 = 1.00`
- `0,2,2` -> `2/3 ≈ 0.67`
- `0,1,2` -> `1/3 ≈ 0.33`

### 题目整体一致率

整题一致率为所有维度一致率的平均值，用于：

- 辅助复核员快速判断争议程度
- 辅助管理员识别高风险题目

## 3.4 推荐值生成规则

当某个维度存在多数时：

- 系统直接采用最高票对应的层级值作为 `recommended_level_value`

当某个维度没有多数时：

- 系统仍会给出一个“参考推荐值”
- 参考推荐值按票数优先
- 若票数相同，则按标注员 `confidence_level` 的加权分值排序

但是必须注意：

- 该参考值只用于辅助复核
- 不会直接作为最终结果落库

## 4. 并行标注与进度同步

## 4.1 并行领取

系统支持同一道题被多个标注员并行领取，不再采用“第一个人领取后整题锁死”的模式。

约束如下：

- 同一个标注员不能重复领取同一道题
- 已提交过最终标注的标注员不能再次领取同一道题
- 题目只有在“已提交人数 + 进行中人数 < required_annotations”时才允许继续被领取

## 4.2 实时进度

系统为每个标注任务实时展示：

- 已提交人数
- 并行进行中人数
- 要求标注人数
- 剩余需要补充的人数
- 百分比进度

这样标注员在标注页就能看到当前题目是否已经接近收敛。

## 5. 争议处理机制

## 5.1 自动进入复核

当任意维度出现 `DISPUTED` 时：

- 系统自动创建复核任务
- 题目状态切换到 `REVIEW_PENDING`

## 5.2 复核员职责

复核员可以看到：

- 题目原文
- 三位标注员的标注结果
- 每位标注员的确信程度
- 各维度投票分布
- 系统推荐结果
- 一致率和未解决维度数
- 历史审核日志

在复核界面中：

- 已达成一致的维度会自动锁定
- 只有 `DISPUTED` 的素养维度需要复核员补充最终结论
- 页面会展示当前待复核池剩余题量
- 复核员可以自行选择每次领取多少道复核题

复核员提交后：

- 题目可直接进入 `COMPLETED`
- 同时关闭其他未完成复核任务

## 5.3 管理员职责

管理员可以在题池详情中看到：

- 当前标注状态
- 已提交人数 / 进行中人数 / 要求人数
- 每位标注员的标注结果
- 每个维度的投票分布
- 推荐值与一致率
- 审核日志与操作历史

管理员的职责以“查看与追踪”为主：

- 查看三位标注员与复核员的处理链路
- 查看哪些素养维度存在争议、最终由谁定稿
- 借助日志追踪题目如何从三人标注流转到复核完成

管理员不再承担日常争议题的手动打回工作，系统会把争议题直接推入复核员队列。

## 6. 审核日志与操作历史

为保证多人标注过程可追溯，系统为每道题维护题目级审阅事件流。

当前记录的主要事件包括：

- 标注员提交标注
- 系统自动完成多数聚合
- 系统创建争议复核任务
- 复核员领取复核任务
- 复核员提交复核结论
- 系统关闭待处理复核任务
- 复核链路完成后的题目归档信息

每条日志记录包含：

- 题目 ID
- 聚合 ID
- 复核任务 ID
- 操作人 ID
- 操作人角色
- 操作类型
- 备注说明
- 附加明细
- 操作时间

这使得系统不仅能看到最终结果，还能回放“这道题是如何走到当前结论的”。

## 7. 任务分配策略

## 7.1 标注员领取规则

标注员进入标注页后，可以自行选择本次领取多少道题。

系统在分配时遵循以下约束：

- 同一道题支持多人并行标注
- 同一标注员不能重复领取同一道题
- 题目只有在“已提交人数 + 进行中人数 < required_annotations”时才能继续被领取

## 7.2 复核员领取规则

复核员进入复核页后，也可以自行选择本次领取多少道复核题。

系统在分配时遵循以下规则：

- 只从 `REVIEW_PENDING` 队列中领取
- 优先领取仍存在未解决争议维度的题
- 一道题一旦被复核员提交完成，就关闭其余待处理复核任务

## 7.3 当前排序规则

题目认领时按以下优先级排序：

1. 优先处理已经有人参与、但还未收敛的题目  
   即 `annotation_count > 0` 且仍未达到 `required_annotations` 的题目

2. 对这类题目，过滤掉已参与过该题的标注员  
   包括：
   - 已提交过该题标注的人
   - 历史上已领取过该题的人

3. 再分配普通新题

这样可以优先推动“快要完成”或“正在并行标注”的题目先收敛。

## 8. 典型流程示例

### 场景 A：三人多数一致，自动完成

某题某个素养维度投票为：

- A：`2`
- B：`2`
- C：`0`

结果：

- 该维度为 `MAJORITY`
- 若所有维度都至少达到 `MAJORITY`
- 题目自动聚合完成
- 写入系统自动聚合日志

### 场景 B：三人完全分散，进入复核

某题某个素养维度投票为：

- A：`0`
- B：`1`
- C：`2`

结果：

- 该维度为 `DISPUTED`
- 题目进入 `REVIEW_PENDING`
- 系统创建复核任务
- 写入争议创建日志

### 场景 C：争议题直接流入复核员队列

某题已有三人标注，但某个素养维度投票为 `0 / 1 / 2`。

系统处理：

- 该维度标记为 `DISPUTED`
- 已一致的维度直接锁定
- 题目进入 `REVIEW_PENDING`
- 复核员在待复核池中看到该题，并可按自定义数量领取
- 复核页展示三位标注员的结果、确信程度、投票分布和操作日志

## 9. 结论

本方案明确了多人标注阶段的三件核心事情：

1. `0` 是正式有效票，表示“无此素养”  
2. 一致性按“维度”逐个判断，而不是整题一票  
3. 无多数的维度直接进入复核，而不是强行自动决策

相较于基础版三人标注流程，`V5` 阶段的这套方案进一步补齐了：

- 一致性定义清晰化
- 争议流转标准化
- 审核过程可追溯
- 复核工作台更完整

这为后续继续建设以下能力打下了基础：

- 高争议题监控
- 标注员质量分析
- 复核效率优化
- 审计与回滚能力
