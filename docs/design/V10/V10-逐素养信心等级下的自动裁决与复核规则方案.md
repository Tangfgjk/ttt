# V10 逐素养信心等级下的自动裁决与复核规则方案

## 1. 背景

当前系统已经支持多人标注、自动聚合和复核员最终裁决。V5 阶段的核心规则是：

- 1 人标注：标注完成后直接形成结果。
- 2 人标注：只要某个素养两人不一致，该题进入复核。
- 3 人标注：2 人一致时按多数聚合，3 人全不一致时进入复核。

V10 之前，信心等级主要是题目级字段。现在已改为“每个核心素养一个信心等级”，因此系统可以在“层级不一致但并非重大分歧”的场景中进行更细的自动裁决，从而减少复核员处理量。

本方案只处理“标注分歧复核”，不处理“判重复核”。

## 2. 目标

1. 在尽可能保证准确性的前提下减少进入待复核池的题目。
2. 让自动裁决规则可解释、可追踪、可展示。
3. 明确 1 人、2 人、3 人标注模式下每种情况的处理方式。
4. 明确“重大分歧”的定义。
5. 本系统暂不设置补票流程，无法自动裁决的情况直接进入复核。

## 3. 基本概念

### 3.1 素养层级

每个核心素养的标注值为：

| 值 | 含义 |
| --- | --- |
| `L0` | 不标注该素养，即认为该题不体现该素养 |
| `L1` | 该素养弱体现 |
| `L2` | 该素养中等体现 |
| `L3` | 该素养强体现 |

本方案以“单个素养”为最小裁决单元。

### 3.2 信心等级

每个标注员对每个素养都需要给出信心等级：

| 信心等级 | 权重 | 含义 |
| --- | ---: | --- |
| 高 | 5 | 标注员对该素养层级判断很确定 |
| 中 | 3 | 标注员有一定把握，但仍可能存在边界判断 |
| 低 | 1 | 标注员不确定，倾向于保留判断 |

历史数据若没有逐素养信心等级，统一按“高”补齐。但历史默认高信心不是标注员真实表达的信心，涉及历史题自动裁决升级时应保守处理。

### 3.3 分歧类型

| 分歧类型 | 示例 | 风险等级 | 说明 |
| --- | --- | --- | --- |
| 无分歧 | `L2 / L2` | 低 | 完全一致 |
| 相邻层级分歧 | `L1 / L2`、`L2 / L3` | 中低 | 都认为有该素养，只是强弱差一级 |
| 跨级层级分歧 | `L1 / L3` | 中高 | 都认为有该素养，但强弱判断差两级 |
| 有无素养分歧 | `L0 / L1`、`L0 / L2`、`L0 / L3` | 高 | 一方认为没有该素养，一方认为有该素养 |
| 三方完全分散 | `L0 / L1 / L2`、`L1 / L2 / L3` | 视情况 | 需要结合是否包含 `L0` 和信心等级 |

## 4. 总体裁决原则

### 4.1 处理顺序

每道题按以下顺序处理：

1. 对每个素养分别收集所有标注员的 `level_value` 和 `confidence_level`。
2. 对每个素养执行本方案中的**自动裁决**或**复核判定**。
3. 只要任意一个素养被判为 `NEED_REVIEW`，整题进入待复核池。
4. 如果所有素养均可自动裁决，整题自动完成。
5. 自动完成时，聚合结果写入 `question_label_aggregates` 和 `question_aggregate_competencies`。
6. 自动裁决原因写入审计日志。

### 4.2 维度级结果状态

每个素养的裁决结果应归入以下状态之一：

| 状态 | 含义 | 是否进入复核 |
| --- | --- | --- |
| `AUTO_SINGLE` | 1 人标注直接采用 | 否 |
| `AUTO_UNANIMOUS` | 所有标注员完全一致 | 否 |
| `AUTO_MAJORITY` | 3 人标注中存在 2 人多数，且未触发重大分歧 | 否 |
| `AUTO_CONFIDENCE` | 无完全一致，但可依据信心等级自动裁决 | 否 |
| `AUTO_CONSERVATIVE` | 相邻层级且信心相同，采用保守取低 | 否 |
| `NEED_REVIEW` | 重大分歧或无法可靠裁决 | 是 |

### 4.3 不设置补票

V10 明确不引入补票流程。

所有无法自动裁决的情况都进入待复核池，由复核员给出最终结论。

## 5. 1 人标注规则

1 人标注模式下，系统不进行额外复核判断。

| 情况 | 处理方式 | 说明 |
| --- | --- | --- |
| 任意 `L0/L1/L2/L3` | 直接采用该标注员结果 | 该模式本身使用较少，保持简单 |
| 非 0 素养低信心 | 仍直接采用 | 可在后续质量分析中标记，但不进复核 |
| 全部素养为 `L0` | 直接采用 | 不单独触发复核 |

整题结果：

- 标注员提交后，题目直接进入已完成状态。
- 不创建复核任务。

## 6. 2 人标注规则

2 人标注模式下，需要区分“层级分歧”和“有无素养分歧”。

### 6.1 两人一致

| 情况 | 示例 | 处理方式 |
| --- | --- | --- |
| 两人都是 `L0` | `L0 / L0` | 自动通过，结果 `L0` |
| 两人都是同一非 0 层级 | `L1 / L1`、`L2 / L2`、`L3 / L3` | 自动通过，结果为一致层级 |

结果状态：`AUTO_UNANIMOUS`

### 6.2 两人都标注了该素养，但层级不一致

这里指两人结果都在 `L1/L2/L3` 内，不包含 `L0`。

#### 6.2.1 信心等级不同

| 情况 | 示例 | 处理方式 |
| --- | --- | --- |
| 一方信心更高 | `L1 高 / L2 中` | 采用信心更高的一方 |
| 一方信心更高 | `L3 高 / L1 低` | 采用信心更高的一方 |

结果状态：`AUTO_CONFIDENCE`

说明：

- 两人都认为该素养存在，因此不是“有无素养”的重大分歧。
- 信心等级可以用于裁决层级强弱。

#### 6.2.2 相邻层级且信心相同

| 情况 | 示例 | 处理方式 |
| --- | --- | --- |
| `L1` 与 `L2`，信心相同 | `L1 高 / L2 高` | 保守取低，结果 `L1` |
| `L2` 与 `L3`，信心相同 | `L2 中 / L3 中` | 保守取低，结果 `L2` |

结果状态：`AUTO_CONSERVATIVE`

说明：

- 题目难度不能直接等同于素养层级，因此不建议用难度作为主裁决依据。
- 为避免过标，默认保守取低一档。
- 若后续业务希望更积极，也可以配置为“取高”，但 V10 默认取低。

#### 6.2.3 跨级层级分歧且信心相同

| 情况 | 示例 | 处理方式 |
| --- | --- | --- |
| `L1` 与 `L3`，信心相同 | `L1 高 / L3 高` | 进入复核 |
| `L1` 与 `L3`，信心相同 | `L1 中 / L3 中` | 进入复核 |
| `L1` 与 `L3`，信心相同 | `L1 低 / L3 低` | 进入复核 |

结果状态：`NEED_REVIEW`

说明：

- `L1` 与 `L3` 差异过大，表示对该素养在题目中的作用强弱判断完全不同。
- 信心相同无法可靠裁决，直接复核。

### 6.3 一人标注该素养，一人未标注

这里指 `L0` 与 `L1/L2/L3` 的分歧。

| 情况 | 示例 | 处理方式 |
| --- | --- | --- |
| `L0` vs `L1` | `L0 高 / L1 高` | 进入复核 |
| `L0` vs `L1` | `L0 低 / L1 高` | 进入复核 |
| `L0` vs `L2` | `L0 中 / L2 低` | 进入复核 |
| `L0` vs `L3` | 任意信心组合 | 进入复核 |

结果状态：`NEED_REVIEW`

说明：

- `L0` 与非 0 的差异不是普通层级差异，而是“该素养是否存在”的判断差异。
- 这类情况统一定义为重大分歧。
- 2 人标注不设置补票，因此直接进入复核。

### 6.4 2 人标注汇总表

| 两人结果 | 信心关系 | 处理方式 | 是否复核 |
| --- | --- | --- | --- |
| `L0 / L0` | 任意 | 自动 `L0` | 否 |
| `L1 / L1`、`L2 / L2`、`L3 / L3` | 任意 | 自动一致层级 | 否 |
| `L1 / L2` | 信心不同 | 取高信心 | 否 |
| `L2 / L3` | 信心不同 | 取高信心 | 否 |
| `L1 / L2` | 信心相同 | 取低，结果 `L1` | 否 |
| `L2 / L3` | 信心相同 | 取低，结果 `L2` | 否 |
| `L1 / L3` | 信心不同 | 取高信心 | 否 |
| `L1 / L3` | 信心相同 | 进入复核 | 是 |
| `L0 / L1` | 任意 | 进入复核 | 是 |
| `L0 / L2` | 任意 | 进入复核 | 是 |
| `L0 / L3` | 任意 | 进入复核 | 是 |

## 7. 3 人标注规则

3 人标注模式下，保留“少数服从多数”的基本原则，但在重大分歧场景中允许打断多数规则进入复核。

### 7.1 三人完全一致

| 情况 | 示例 | 处理方式 |
| --- | --- | --- |
| 三人都是 `L0` | `L0 / L0 / L0` | 自动 `L0` |
| 三人都是同一非 0 层级 | `L2 / L2 / L2` | 自动一致层级 |

结果状态：`AUTO_UNANIMOUS`

### 7.2 2 人多数，且未触发重大分歧

| 情况 | 示例 | 处理方式 |
| --- | --- | --- |
| 多数为非 0，少数为相邻非 0 | `L2 / L2 / L3` | 自动 `L2` |
| 多数为非 0，少数为跨级非 0 | `L1 / L1 / L3` | 默认自动 `L1`，除非触发重大分歧 |
| 多数为 `L0`，少数为低信心非 0 | `L0 高 / L0 中 / L1 低` | 自动 `L0` |
| 多数为非 0，少数为低/中信心 `L0` | `L2 高 / L2 中 / L0 低` | 自动 `L2` |

结果状态：`AUTO_MAJORITY`

说明：

- 多数规则仍是 3 人标注的主规则。
- 少数意见不会因为“信心高”就直接推翻多数。
- 只有满足“重大分歧”定义时，才进入复核。

### 7.3 2 人多数但触发重大分歧

以下情况虽然存在 2 人多数，但不应自动通过。

#### 7.3.1 多数方低信心，少数方高信心，且涉及有无素养

| 情况 | 示例 | 处理方式 |
| --- | --- | --- |
| 多数认为有，少数高信心认为无 | `L1 低 / L1 低 / L0 高` | 进入复核 |
| 多数认为有，少数高信心认为无 | `L2 低 / L2 低 / L0 高` | 进入复核 |
| 多数认为无，少数高信心认为有 | `L0 低 / L0 低 / L2 高` | 进入复核 |
| 多数认为无，少数高信心认为有 | `L0 低 / L0 低 / L3 高` | 进入复核 |

结果状态：`NEED_REVIEW`

说明：

- 这类情况说明多数方本身不确定，而少数方对相反判断很确定。
- 因为涉及 `L0` 与非 0，属于“是否体现该素养”的重大分歧。

#### 7.3.2 多数方低信心，少数方高信心，且跨度为 `L1` 与 `L3`

| 情况 | 示例 | 处理方式 |
| --- | --- | --- |
| 多数 `L1` 低信心，少数 `L3` 高信心 | `L1 低 / L1 低 / L3 高` | 进入复核 |
| 多数 `L3` 低信心，少数 `L1` 高信心 | `L3 低 / L3 低 / L1 高` | 进入复核 |

结果状态：`NEED_REVIEW`

说明：

- 都认为该素养存在，但对“弱体现”和“强体现”的判断完全相反。
- 多数方低信心时，不应强行多数通过。

#### 7.3.3 多数方不是低信心时

| 情况 | 示例 | 处理方式 |
| --- | --- | --- |
| 多数方至少一人中/高信心 | `L2 高 / L2 低 / L0 高` | 自动多数 `L2` |
| 多数方两人都是中信心 | `L0 中 / L0 中 / L2 高` | 自动多数 `L0` |
| 多数方一高一中 | `L1 高 / L1 中 / L3 高` | 自动多数 `L1` |

结果状态：`AUTO_MAJORITY`

说明：

- 只要多数方不是“两人都低信心”，多数规则仍优先。
- 少数高信心可以记录为“高信心少数异议”，但不进入复核。

### 7.4 三人无多数且全为非 0

这里指 `L1/L2/L3` 三个层级各出现一次。

| 情况 | 示例 | 处理方式 |
| --- | --- | --- |
| 有唯一最高信心 | `L1 低 / L2 高 / L3 中` | 取最高信心对应层级，结果 `L2` |
| 最高信心并列但包含中位层级 | `L1 高 / L2 高 / L3 中` | 取中位层级 `L2` |
| 三人信心相同 | `L1 高 / L2 高 / L3 高` | 取中位层级 `L2` |
| 两个极端层级高信心，中位低信心 | `L1 高 / L2 低 / L3 高` | 进入复核 |

默认结果状态：

- 可裁决时：`AUTO_CONFIDENCE` 或 `AUTO_CONSERVATIVE`
- 极端冲突时：`NEED_REVIEW`

说明：

- 三人都认为该素养存在，因此不是“有无素养”的重大分歧。
- `L1/L2/L3` 这种连续层级分散可以用中位数或信心等级裁决。
- 但 `L1 高` 与 `L3 高` 同时存在，且 `L2` 低信心时，说明弱/强判断冲突明显，应复核。

### 7.5 三人无多数且包含 `L0`

这里指以下组合：

- `L0 / L1 / L2`
- `L0 / L1 / L3`
- `L0 / L2 / L3`

处理方式：进入复核。

| 情况 | 示例 | 处理方式 |
| --- | --- | --- |
| `L0/L1/L2` | 任意信心组合 | 进入复核 |
| `L0/L1/L3` | 任意信心组合 | 进入复核 |
| `L0/L2/L3` | 任意信心组合 | 进入复核 |

结果状态：`NEED_REVIEW`

说明：

- 包含 `L0` 且无多数，说明“是否体现该素养”没有形成稳定意见。
- 不设置补票，因此直接复核。

### 7.6 3 人标注汇总表

| 三人结果形态 | 示例 | 处理方式 | 是否复核 |
| --- | --- | --- | --- |
| 三人完全一致 | `L2/L2/L2` | 自动一致层级 | 否 |
| 2 人多数，非重大分歧 | `L2/L2/L3` | 自动多数 | 否 |
| 2 人多数，多数方两低，少数方高，且 `L0` vs 非 0 | `L1 低 / L1 低 / L0 高` | 进入复核 | 是 |
| 2 人多数，多数方两低，少数方高，且 `L1` vs `L3` | `L1 低 / L1 低 / L3 高` | 进入复核 | 是 |
| 无多数，全为非 0，最高信心唯一 | `L1 低 / L2 高 / L3 中` | 取最高信心 | 否 |
| 无多数，全为非 0，信心相同 | `L1 高 / L2 高 / L3 高` | 取中位数 `L2` | 否 |
| 无多数，全为非 0，极端高信心冲突 | `L1 高 / L2 低 / L3 高` | 进入复核 | 是 |
| 无多数，包含 `L0` | `L0/L1/L2` | 进入复核 | 是 |

## 8. 重大分歧定义

以下情况统一定义为重大分歧。

### 8.1 2 人标注重大分歧

| 编号 | 情况 | 示例 |
| --- | --- | --- |
| D2-1 | 一人 `L0`，一人非 0 | `L0 / L1`、`L0 / L2`、`L0 / L3` |
| D2-2 | 两人都是非 0，但层级跨度为 2 且信心相同 | `L1 高 / L3 高` |

### 8.2 3 人标注重大分歧

| 编号 | 情况 | 示例 |
| --- | --- | --- |
| D3-1 | 多数方两人低信心，少数方高信心，且涉及 `L0` vs 非 0 | `L2 低 / L2 低 / L0 高` |
| D3-2 | 多数方两人低信心，少数方高信心，且涉及 `L1` vs `L3` | `L1 低 / L1 低 / L3 高` |
| D3-3 | 三人无多数且包含 `L0` | `L0 / L1 / L2` |
| D3-4 | 三人无多数，全为非 0，但极端层级 `L1` 和 `L3` 均为高信心，中位 `L2` 为低信心 | `L1 高 / L2 低 / L3 高` |

### 8.3 不作为重大分歧的情况

| 情况 | 示例 | 处理方式 |
| --- | --- | --- |
| 3 人中 2 人多数，且多数方不是两低信心 | `L2 高 / L2 低 / L0 高` | 自动多数 |
| 2 人都是非 0，相邻层级且信心相同 | `L1 高 / L2 高` | 保守取低 |
| 3 人无多数，全为非 0 且没有极端高信心冲突 | `L1 中 / L2 高 / L3 中` | 按信心或中位数裁决 |

## 9. 整题流转规则

对一道题，系统应对每个素养生成维度级裁决结果。

### 9.1 自动完成

若所有素养均为以下状态，则整题自动完成：

- `AUTO_SINGLE`
- `AUTO_UNANIMOUS`
- `AUTO_MAJORITY`
- `AUTO_CONFIDENCE`
- `AUTO_CONSERVATIVE`

题目状态进入 `COMPLETED`。

### 9.2 进入待复核池

若任意一个素养为 `NEED_REVIEW`，则整题进入 `REVIEW_PENDING`。

复核员页面中：

- `NEED_REVIEW` 的素养默认进入可编辑区域。
- 自动裁决的素养默认锁定。
- 复核员仍可手动解锁自动裁决素养并修改。

### 9.3 复核提交

复核员提交后：

- 复核结果覆盖该题最终聚合结果。
- 题目状态进入 `COMPLETED`。
- 当前题目的其他未完成复核任务关闭。
- 审计日志记录复核员、复核时间、复核原因和最终矩阵。

## 10. 自动裁决理由记录

为了让管理员和复核员理解系统为何自动裁决，建议在聚合日志中记录以下字段。

### 10.1 维度级裁决明细

建议在 `AnnotationReviewLog.detail_json` 中保存：

```json
{
  "decision_version": "V10",
  "dimension_decisions": [
    {
      "competency_id": 1,
      "competency_name": "抽象能力",
      "final_level": 2,
      "decision_status": "AUTO_CONFIDENCE",
      "reason_code": "TWO_ANNOTATORS_NON_ZERO_CONFIDENCE_WIN",
      "votes": [
        {
          "annotator_id": 10,
          "level_value": 1,
          "confidence_level": 3
        },
        {
          "annotator_id": 11,
          "level_value": 2,
          "confidence_level": 5
        }
      ]
    }
  ]
}
```

### 10.2 推荐 reason_code

| reason_code | 含义 |
| --- | --- |
| `SINGLE_ANNOTATOR_ACCEPTED` | 1 人标注直接采用 |
| `UNANIMOUS_ACCEPTED` | 完全一致 |
| `MAJORITY_ACCEPTED` | 多数通过 |
| `TWO_ANNOTATORS_NON_ZERO_CONFIDENCE_WIN` | 2 人均非 0，信心高者胜出 |
| `TWO_ANNOTATORS_ADJACENT_SAME_CONFIDENCE_LOW_LEVEL` | 2 人相邻层级且信心相同，保守取低 |
| `THREE_ANNOTATORS_NON_ZERO_CONFIDENCE_WIN` | 3 人无多数但全非 0，按信心裁决 |
| `THREE_ANNOTATORS_NON_ZERO_MEDIAN` | 3 人无多数但全非 0，取中位数 |
| `REVIEW_REQUIRED_ZERO_NON_ZERO` | `L0` 与非 0 重大分歧 |
| `REVIEW_REQUIRED_MAJOR_LOW_MINOR_HIGH` | 多数方低信心、少数方高信心的重大分歧 |
| `REVIEW_REQUIRED_WIDE_GAP_SAME_CONFIDENCE` | `L1` 与 `L3` 跨级且信心相同 |
| `REVIEW_REQUIRED_EXTREME_HIGH_CONFLICT` | 三人无多数且极端高信心冲突 |

## 11. 前端展示建议

### 11.1 标注员提交结果

复核页和管理员查看页应继续以标注员为单位展示：

- 每位标注员一张卡片。
- `L0` 灰色弱化。
- `L1` 蓝色。
- `L2` 紫色。
- `L3` 玫红色。
- 显示逐素养信心等级。

### 11.2 自动裁决结果

管理员查看题目时建议展示：

- 最终层级。
- 裁决状态，如“多数通过”“信心裁决”“保守取低”“进入复核”。
- 触发原因，如“两人均标注该素养，信心高者胜出”。

### 11.3 复核页

复核页建议：

- 默认只展开 `NEED_REVIEW` 素养。
- 自动裁决素养默认锁定。
- 对自动裁决素养显示裁决理由。
- 允许复核员确认后解锁修改。

## 12. 实现建议

### 12.1 后端裁决函数

建议新增维度级裁决函数：

```python
def decide_competency_dimension(votes: list[CompetencyVote], required_annotations: int) -> CompetencyDecision:
    ...
```

输入：

- `competency_id`
- 每个标注员的 `level_value`
- 每个标注员的 `confidence_level`
- `required_annotations`

输出：

- `final_level`
- `decision_status`
- `reason_code`
- `need_review`
- `vote_summary`

### 12.2 聚合函数改造

当前 `_build_consensus_dimension` 只判断：

- 全一致：`UNANIMOUS`
- 至少 2 票一致：`MAJORITY`
- 否则：`DISPUTED`

V10 应将其升级为：

- 先判断 1/2/3 人模式。
- 再按本方案做维度级自动裁决。
- 最后汇总整题是否 `NEED_REVIEW`。

### 12.3 数据兼容

历史数据中的逐素养信心等级若由迁移默认补成高信心，应在自动裁决日志中标记：

```json
{
  "confidence_source": "migration_default"
}
```

如果当前数据模型暂时无法区分真实高信心与迁移默认高信心，则历史题可以采用保守策略：

- 新提交标注使用 V10 自动裁决。
- 已经进入复核池的历史题不批量重算，仍由复核员处理。

## 14. 与 V5 规则的差异

| 项目 | V5 | V10 |
| --- | --- | --- |
| 信心等级 | 题目级或仅辅助展示 | 逐素养参与裁决 |
| 2 人不一致 | 直接复核 | 层级分歧可自动裁决，有无素养分歧复核 |
| 3 人 2:1 | 默认多数 | 默认多数，但重大分歧可复核 |
| 3 人全不一致 | 直接复核 | 全非 0 可按信心/中位数裁决，含 `L0` 复核 |
| 补票 | 不作为主流程 | 明确不设置补票 |
| 审计日志 | 记录聚合/复核事件 | 增加维度级裁决理由 |

## 15. 推荐落地顺序

1. 增加后端维度级裁决函数和单元测试。
2. 保留现有数据库结构，先将裁决理由写入 `AnnotationReviewLog.detail_json`。
3. 修改 `_aggregate_question`，按 V10 规则生成聚合结果与复核任务。
4. 复核页展示 `NEED_REVIEW` 素养和自动裁决理由。
5. 管理员题目审查页展示每个素养的裁决状态。
6. 先对新提交标注启用 V10；历史已进入复核池题目不强制重算。
