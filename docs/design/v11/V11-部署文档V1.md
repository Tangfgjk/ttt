# V11-部署文档V1

本文记录 K12 学科标注平台在阿里云 ECS 上的部署、更新、备份和故障处理流程。本文以当前实际部署环境为准，作为后续多人标注试运行的第一版部署文档。

生产式试运行入口：

```text
http://47.98.118.198
```

服务器运行目录：

```text
/opt/ttt
```

本文不记录真实密码。真实配置只保存在服务器：

```text
/opt/ttt/app/deploy/compose/.env
```

## 1. 当前部署结论

当前系统已经可以通过 Docker Compose 在阿里云 ECS 上运行，服务包括：

```text
ttt-nginx    前端静态资源和 HTTP 入口，监听 80
ttt-backend  FastAPI 后端接口，容器内 8000
ttt-worker   Celery 后台任务
ttt-mysql    MySQL 8.4，正式业务数据库
ttt-redis    Redis 队列和缓存
```

检查服务状态：

```bash
cd /opt/ttt/app/deploy/compose
docker compose --env-file .env ps
```

正常状态应类似：

```text
ttt-backend  Up ... healthy
ttt-mysql    Up ... healthy
ttt-nginx    Up ... 0.0.0.0:80->80/tcp
ttt-redis    Up ... healthy
ttt-worker   Up
```

## 2. 服务器目录约定

服务器统一使用 `/opt/ttt`：

```text
/opt/ttt/app        GitHub 仓库代码
/opt/ttt/mysql      MySQL 持久化数据目录
/opt/ttt/redis      Redis 持久化数据目录
/opt/ttt/uploads    上传文件目录
/opt/ttt/artifacts  训练和导入产物目录
/opt/ttt/models     模型目录
/opt/ttt/backups    数据库和文件备份目录
```

重要原则：

```text
GitHub 管代码
MySQL 管正式标注数据
/opt/ttt/uploads 和 /opt/ttt/artifacts 管运行文件
/opt/ttt/models 管本地模型
.env 管服务器私有配置，不提交 GitHub
```

不要删除：

```text
/opt/ttt/mysql
/opt/ttt/uploads
/opt/ttt/artifacts
/opt/ttt/models
```

## 3. 当前数据主从约定

当前正式数据源是云服务器 MySQL。

```text
云服务器数据库：正式主库，保存多人标注产生的数据
本地数据库：开发和备份副本，不再覆盖云服务器
GitHub：只保存代码，不保存数据库和运行数据
```

后续不能把本地旧 SQL 重新导入云服务器覆盖主库。需要同步数据时，应从云服务器导出备份，再下载到本地。

## 4. 日常代码更新流程

### 4.1 本地提交并推送 GitHub

本地开发完成后，在本地仓库执行：

```powershell
cd C:\Users\29694\Desktop\ttt
git status
git add .
git commit -m "本次修改说明"
git push origin master
```

如果 `git status` 出现不确定的文件，先不要 `git add .`，确认后再提交。

### 4.2 云服务器部署前先备份数据库

每次更新代码前，建议先备份正式数据库：

```bash
mkdir -p /opt/ttt/backups

docker exec ttt-mysql mysqldump \
  -uroot \
  -p你的MYSQL_ROOT_PASSWORD \
  --default-character-set=utf8mb4 \
  --single-transaction \
  --routines \
  --triggers \
  --events \
  ttt_prod \
  | gzip > /opt/ttt/backups/ttt_prod_before_update_$(date +%F_%H%M%S).sql.gz

ls -lh /opt/ttt/backups/ | tail
```

说明：

- 这一步不会影响线上运行。
- 文件名里包含时间，方便回滚。
- 不要把 `.sql` 或 `.sql.gz` 提交到 GitHub。

### 4.3 云服务器拉取代码并重新部署

```bash
cd /opt/ttt/app
git pull origin master
git log --oneline -3

cd /opt/ttt/app/deploy/compose
docker compose --env-file .env up -d --build
docker compose --env-file .env ps
```

如果只是代码修改、数据库字段没有变，一般不需要手动导入 SQL，也不需要手动执行迁移。

如果后续新增 Alembic 迁移文件，再执行：

```bash
cd /opt/ttt/app/deploy/compose
docker compose --env-file .env --profile tools run --rm migrate
docker compose --env-file .env up -d --build
```

先确认本地目标库，再导入。不要把云端备份导回云端覆盖，除非是在明确做灾难恢复。

```powershell
gzip -d ttt_prod_时间.sql.gz
mysql -uroot -p 本地数据库名 < ttt_prod_时间.sql
```

## 7. 本次部署遇到的问题与处理

### 7.1 校园网跨设备无法访问本地 Vite 服务

现象：

```text
图 1 电脑无法访问 http://10.131.201.92:5173/
Test-NetConnection 10.131.201.92 -Port 5173 失败
Ping 也超时
```

原因判断：

- Vite 开发服务即使监听 `0.0.0.0:5173`，也只表示本机所有网卡可监听。
- 校园网可能隔离不同网段或不同登录设备。
- 防火墙放行端口后仍可能被校园网策略拦截。

处理结论：

```text
本地开发服务不适合作为多人访问入口。
多人标注应部署到公网云服务器。
```

### 7.2 Windows 防火墙添加规则提示拒绝访问

现象：

```powershell
New-NetFirewallRule ... -LocalPort 5173
New-NetFirewallRule : 拒绝访问。
```

原因：

```text
PowerShell 没有以管理员权限运行。
```

处理：

```text
用管理员身份打开 PowerShell 后重新执行。
```

后续因为改为云服务器部署，本地防火墙问题不再作为主方案处理。

### 7.3 Docker 官方源 GPG 或连接失败

现象：

```text
curl: (35) OpenSSL SSL_connect: Connection reset by peer
NO_PUBKEY 7EA0A9C3F273FCD8
The repository 'https://download.docker.com/linux/ubuntu jammy InRelease' is not signed.
```

原因：

```text
服务器访问 Docker 官方源不稳定，GPG key 没有成功下载。
```

处理：改用阿里云 Docker CE 源。

```bash
rm -f /etc/apt/sources.list.d/docker.list
rm -f /etc/apt/keyrings/docker.asc

install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://mirrors.aliyun.com/docker-ce/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc

echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://mirrors.aliyun.com/docker-ce/linux/ubuntu jammy stable" > /etc/apt/sources.list.d/docker.list

apt update
apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

systemctl enable docker
systemctl start docker

docker --version
docker compose version
```

### 7.4 Docker Hub 拉镜像超时

现象：

```text
failed to resolve reference "docker.io/library/mysql:8.4"
dial tcp ... i/o timeout
```

原因：

```text
服务器访问 Docker Hub 不稳定。
```

处理：配置 Docker 镜像加速。

```bash
mkdir -p /etc/docker

cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.1ms.run",
    "https://docker.xuanyuan.me"
  ]
}
EOF

systemctl daemon-reload
systemctl restart docker
docker info | grep -A 10 "Registry Mirrors"
```

### 7.5 GitHub private 仓库 HTTPS clone 卡住或失败

现象：

```text
git clone https://github.com/Tangfgjk/ttt.git app
Username for 'https://github.com':
Password for 'https://...':
fatal: unable to access ... Error in the HTTP2 framing layer
```

原因：

```text
GitHub 私有仓库不能直接用账号密码拉取。
HTTPS token 在终端中容易误粘贴、泄露或连接失败。
```

处理：服务器使用 SSH Deploy Key，并让 SSH 走 443 端口。

```bash
mkdir -p ~/.ssh
ssh-keygen -t ed25519 -C "aliyun-ecs-ttt" -f ~/.ssh/id_ed25519 -N ""
cat ~/.ssh/id_ed25519.pub
```

把输出的公钥添加到 GitHub 仓库 Deploy keys。

服务器配置：

```bash
cat > ~/.ssh/config <<'EOF'
Host github.com
  HostName ssh.github.com
  Port 443
  User git
  IdentityFile ~/.ssh/id_ed25519
EOF

chmod 600 ~/.ssh/config
ssh -T git@github.com
```

成功提示：

```text
You've successfully authenticated, but GitHub does not provide shell access.
```

然后拉代码：

```bash
cd /opt/ttt
git clone git@github.com:Tangfgjk/ttt.git app
```

### 7.6 `git pull` 提示本地文件会被覆盖

现象：

```text
error: Your local changes to the following files would be overwritten by merge:
  deploy/docker/backend/Dockerfile
Please commit your changes or stash them before you merge.
```

原因：

```text
服务器上临时手改过代码文件，和 GitHub 最新提交冲突。
```

原则：

```text
服务器不长期手改代码。
正式代码以本地开发后推送到 GitHub 为准。
```

如果服务器临时改动已经同步到 GitHub，可以丢弃服务器临时改动：

```bash
cd /opt/ttt/app
git restore deploy/docker/backend/Dockerfile
git pull origin master
```

如果不确定，不要 restore，先执行：

```bash
git status --short
git diff
```

### 7.7 后端构建反复下载 CUDA 版 PyTorch

现象：

```text
Collecting nvidia-cudnn-cu12
Collecting nvidia-cublas-cu12
Downloading nvidia_cudnn_cu12...
Downloading nvidia_cublas_cu12...
```

或：

```text
libtorch_cuda.so
```

原因：

```text
普通 ECS 是 CPU 服务器，不需要 CUDA 版 PyTorch。
之前 Dockerfile 虽然先安装了 CPU 版 torch，但 pyproject.toml 中仍有 torch>=2.2.0,<2.4.0。
后续 pip install -e . 重新解析依赖时，可能又拉取默认 CUDA 版 torch 及 nvidia 包。
```

处理结果：

已修改 `deploy/docker/backend/Dockerfile`：

```text
1. 先复制 backend/pyproject.toml 和 backend/README.md
2. 从 pyproject.toml 生成去掉 torch 的依赖列表
3. 固定安装 torch==2.3.1+cpu
4. 安装其他依赖时使用 constraints 防止 torch 被替换
5. 再复制业务代码
6. 最后 pip install -e . --no-deps
```

这样后续只改业务代码时，依赖层可以复用缓存，不会每次重新安装全部依赖。

检查 Dockerfile：

```bash
grep -n "torch==2.3.1+cpu" /opt/ttt/app/deploy/docker/backend/Dockerfile
grep -n "pip install -e . --no-deps" /opt/ttt/app/deploy/docker/backend/Dockerfile
```

构建时如果还看到大量 `nvidia-cuda`，应停止构建并重新检查 Dockerfile。

### 7.8 构建失败：磁盘空间不足

现象：

```text
no space left on device
write /var/lib/containerd/.../libtorch_cuda.so
```

原因：

```text
40G 系统盘空间有限。
Docker 构建缓存、旧镜像、CUDA 版 torch 下载层占用大量空间。
```

检查：

```bash
df -h
docker system df
```

安全清理，不删除数据库：

```bash
docker builder prune -af
docker image prune -af
docker container prune -f
docker system df
df -h
```

禁止执行：

```bash
docker compose down -v
docker system prune -af --volumes
rm -rf /opt/ttt/mysql
```

说明：

```text
不带 --volumes 的 prune 不会删除 MySQL 持久化目录。
真正危险的是删除 volume 或删除 /opt/ttt/mysql。
```

长期建议：

```text
40G 只能试运行。
长期多人标注建议系统盘至少 100G，最好 200G。
```

### 7.9 重新构建后旧容器仍在跑

现象：

```text
构建失败，但 docker compose ps 里容器仍然 Up
```

解释：

```text
Docker Compose 构建新镜像失败时，旧容器通常仍会继续运行。
因此网站可能仍能打开，但新代码没有部署成功。
```

确认是否真的更新成功：

```bash
cd /opt/ttt/app
git log --oneline -3

cd /opt/ttt/app/deploy/compose
docker compose --env-file .env up -d --build
docker compose --env-file .env ps
```

只有看到镜像 Built、容器重新 Started/Healthy，才说明新代码部署成功。

## 8. 常用检查命令

本节集中记录云服务器日常维护最常用的命令。执行前先进入 Compose 目录：

查看数据库基本数据：


查看当前标注策略：


查看最近标注数据增长：

```bash

```

查看各题池数量：

```bash
docker exec -it ttt-mysql mysql -uroot -p你的MYSQL_ROOT_PASSWORD -e "USE ttt_prod; SELECT annotation_status, COUNT(*) AS count FROM questions GROUP BY annotation_status ORDER BY annotation_status;"
```

## 11. 当前已知改进建议

1. 长期运行建议扩容系统盘到 100G 或 200G。
2. 建议配置每天自动数据库备份，并定期下载到本地或对象存储。
3. 建议后续配置域名和 HTTPS。
4. 建议 SSH 端口只允许可信 IP 访问。
5. 建议为生产环境单独创建非 root 服务器用户。
6. 建议把大模型文件独立备份，不依赖 GitHub。
